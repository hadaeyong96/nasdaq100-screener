# P3.4 지시문 — 휴대폰용 보고서 + 짧은 텔레그램

---

보고서의 기본 사용 환경은 **PC**야. 사용자는 텔레그램 첨부 보고서를 휴대폰으로 간단히 확인하고, 실제 처리(주문 판단·체결 기록)는 PC에서 해. 그래서 PC 화면(엑셀 같은 표)이 기준이고, 휴대폰 카드 보기는 폭 640px 이하에서만 켜지는 보조 기능이야. 텔레그램 글은 최소로 줄여줘. 스케줄·드라이브는 여전히 만들지 마.

## 1. 보고서 템플릿 교체

- `docs/report_template.html`이 새 버전으로 바뀌었어. 휴대폰 화면(폭 640px 이하)에서 표가 카드로 바뀌는 CSS와, 각 칸에 머리글 이름을 붙이는 스크립트(`data-label`)가 추가됐어. 탭은 위에 고정(sticky)돼.
- `notify/templates/report.html.j2`를 새 템플릿에 맞게 갱신해줘. 구조·클래스 이름·스크립트를 그대로 따를 것.
- 규칙: 각 표의 **첫 칸은 종목**(카드 제목이 됨), 긴 설명은 `class="note"` 칸에 넣기(카드 맨 아래 전체 폭). 빈 표는 `class="empty"` 한 칸.
- 요약줄 순서: 신규 매수 · 매도·손절 · 보유 · 걸러진 신호 · 신규 위험(마지막, 휴대폰에서 한 줄 전체).
- 보고서 하단의 "내 보유 종목" 표는 **삭제**. 체결 기록 안내 줄만 탭 아래에 남긴다. 보유 정보는 "보유 현황" 탭에서만 보여준다.
- 신규 매수 표(1차·2차·3차·재진입)는 **9칸으로 단순화**: 종목 · 결정 · 지정가 · 수량 · 투입금액 · 손절가 · 손절폭 · 점수 · 비고. 지표 근거(RSI 변화, 등급, 거래량 부족, 실적 임박 등)는 비고 한 줄에 요약. 계좌 금액 재계산은 수량·투입금액 칸만 갱신.

## 2. 텔레그램 글은 최소로

첨부 보고서가 본체야. 글은 아래 형식만, 종목은 **티커만** 써줘.

```
📊 나스닥100 · 9/23(화) 마감 · 실전
🟢 매수 2 · CMCSA(1차) PLTR(재진입)
🔴 매도 0
📎 보고서를 열어 확인하세요
```

- 매도가 있으면: `🔴 매도 1 · ROP(전량)` / 손절이면 `ROP(손절)`
- 둘 다 없으면: `오늘 매매 신호 없음` 한 줄 + 보고서 첨부
- 전날 미체결이 있을 때만 한 줄 추가: `⚠️ 미체결 1 · CMCSA`
- 데이터 지연 모드는 지금처럼 지연 알림 한 통 (첨부 없음)
- 첨부 파일 이름은 `나스닥100_2026-09-23.html`처럼 한글 제목 + 날짜로 (휴대폰 파일 목록에서 알아보기 쉽게)

## 3. 다시 보내기 명령

- `python -m engine.daily --resend` : 상태를 다시 처리하지 않고, 마지막 기준일의 보고서와 글을 텔레그램으로 다시 보낸다 (중복 발송 방지 기록은 무시).

## 4. 체결 기록을 엑셀 파일로

사용자가 CSV 입력을 불편해해서, 체결 기록 입력을 엑셀 파일로 바꿔줘.

- 새 입력 파일: `data/fills.xlsx` (사용자가 만든 양식을 넣어 둠). **"체결기록" 시트만** 읽는다. "사용법"·"작성예시" 시트는 읽지 않는다.
- 열: 날짜, 종목, 차수(1차·2차·3차·재진입·대기자금), 매수매도(매수·매도), 체결가, 수량, 금액($)(수식, 무시), 메모(무시).
- 빈 줄은 건너뛰고, 날짜 칸이 엑셀 날짜여도 글자여도 받는다.
- `차수=대기자금`은 쉬는 돈(QQQM) 매매 기록이야. 지금은 읽어서 보유 표에 QQQM 줄로만 보여주고, 신호 판정에는 쓰지 않는다 (QQQM 운용 로직은 P4).
- `data/fills.xlsx`가 있으면 그것을 쓰고, 없으면 기존 `data/fills.csv`를 쓴다. 둘 다 있으면 xlsx 우선 + 경고.
- 기존 `fills.csv`에 기록이 있으면 xlsx "체결기록" 시트로 옮겨 주고 csv는 `fills_csv_backup.csv`로 이름을 바꿔 둔다.
- 엑셀이 파일을 열고 있어 잠겨 있으면(임시 파일 `~$fills.xlsx` 존재 또는 읽기 오류) 실행을 멈추지 말고 "체결 기록 파일이 열려 있음, 저장 후 닫아 주세요" 경고로 처리.
- `.gitignore`에 `data/fills.xlsx`, `~$*.xlsx` 추가. 보고서의 체결 기록 안내 문구와 경로를 `data\fills.xlsx`로 바꿔줘.
- `openpyxl`을 requirements에 추가.
- 테스트: xlsx 읽기(엑셀 날짜·글자 날짜, 빈 줄, 예시 시트 무시, 대기자금 행), 파일 잠김 경고.

## 5. 테스트와 확인

- 보고서: **PC 폭 1440px**에서 표·탭·정렬·계좌 금액 재계산이 정상인지 먼저 확인하고, 휴대폰 폭 390px에서는 카드 보기로 가로 스크롤이 없는지 확인 (가능하면 playwright로 두 폭의 스크린샷을 `outputs/`에 저장)
- 텔레그램 글 형식 테스트 (매수만 / 매도만 / 둘 다 없음 / 미체결 있음)
- `pytest` 전부 통과

## 6. 완료 후

`python -m engine.daily --resend`로 9/23 보고서를 실제로 보내줘. 토큰 값은 절대 출력하지 마.

```
[P3.4 완료 보고]
테스트: 통과 N / 실패 N
텔레그램 글 미리보기: ...
발송 결과: 성공 / 실패(사유)
PC·휴대폰 스크린샷 경로: ...
fills.xlsx 읽기: 읽은 줄 수 / 옮긴 csv 줄 수 / 경고
수정 파일 목록: ...
판단이 필요한 부분: (없으면 "없음")
```

"P3.4 mobile report and short briefing" 메시지로 커밋해줘. 푸시는 하지 마.
