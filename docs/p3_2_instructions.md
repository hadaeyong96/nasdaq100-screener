# P3.2 긴급 보완 지시문 — 기준일 후퇴, 오래된 신호 발송, 보안 규칙

P3.1 보고를 검토했어. 주문대기 로직은 잘 됐지만, 실행 결과에서 심각한 문제 두 개가 나왔어. 아래 순서대로 처리해줘. 스케줄·드라이브는 여전히 만들지 마.

## 0. 보안 규칙 (먼저)

- `.env`나 인증 정보의 **값**은 어떤 경우에도 출력·repr·로그하지 마. 존재 여부와 길이만 확인해.
- CLAUDE.md의 "보안" 항목에 이 규칙을 한 줄 추가해줘.
- `.gitignore`에 `*key*.txt`, `*token*.txt`, `*secret*` 패턴을 추가해줘. 저장소 루트의 `hadaeyong_bot_key.txt`는 열지 말고 그대로 둬 (사용자가 직접 처리함).

## 1. 기준일 후퇴 원인 수정 (최우선)

P3.1 실행에서 기준일이 2026-09-22 → 2026-09-21로 **뒤로 갔어**. 실행 시각(한국 9/23 밤 = 미국 9/23 장중)에는 9/22 봉이 이미 끝난 봉이야. "장중이라 확정 안 됨"이 아니라, 9/22 봉의 일봉 종가가 여전히 비어 있고 meta는 이제 9/23 실시간 가격을 가리켜서 보완이 거절된 거야. 그런데 캐시에는 9/22 meta 보완 종가가 있었어. P1.2에서 만든 캐시 되살리기가 동작하지 않은 거야.

- 새로 받은 일봉 종가가 비어 있으면(NaN) 캐시의 `close_source="meta"` 값을 **덮어쓰지 말고 유지**해야 해. 일봉 배열에 **실제 값이 있을 때만** 캐시 값을 대체한다. 원인을 찾아 고치고 테스트로 재현해줘.
- **예비 종가 출처 추가**: 일봉 종가도, 유효한 meta도, 캐시도 없을 때 다른 출처로 그날 종가를 구한다. 후보를 실제로 시험해보고 되는 걸 써줘: (a) Stooq 일봉 CSV, (b) yfinance 60분봉의 그날 마지막 봉 종가. 가져온 값은 그날 저가~고가 범위 안일 때만 쓰고 `close_source`에 출처를 남겨.
- 과거 봉 중에도 종가가 빈 날이 있으면 같은 방식으로 채워봐. 끝내 못 채우면 기존대로 data_gap.

## 2. 오래된 기준일로 매매 신호를 보내지 않기 (최우선)

기준일이 뒤로 가면서 9/21 기준 신호(CMCSA·FER)가 "오늘 할 일"로 텔레그램에 나갔어. 9/21 신호의 주문일은 이미 지나간 9/22야. 이건 실제 돈 손실로 이어질 수 있는 결함이야.

- 미국 증시 거래일 달력(`pandas_market_calendars`, requirements에 추가)으로 "실행 시각 기준 가장 최근에 **마감된** 거래일"을 계산한다.
- 기준일이 그보다 이전이면 **데이터 지연 모드**:
  - 상태 전이·주문대기 생성·이벤트 기록을 하지 않는다.
  - 텔레그램은 "데이터 지연: 기대 기준일 YYYY-MM-DD, 실제 YYYY-MM-DD. 오늘은 매매 신호 없음" 한 통만 보낸다 (보고서 첨부 없음).
  - 보고서를 만든다면 맨 위에 빨간 배너로 같은 내용을 표시하고 매수 탭은 비운다.
- 기존 주말만 건너뛰던 로직과 config의 공휴일 TODO는 이 달력으로 대체.
- 테스트: 기대 기준일보다 이전이면 상태 변화 0, 발송 글이 지연 알림 한 통.

## 3. 처리 날짜 누락 방지

P3.1 판단 3번 답: `start_date` 대신 `last_processed_date`(마지막으로 처리 완료한 기준일)를 저장하고, 실행할 때마다 그 다음 거래일부터 이번 기준일까지 **모든 거래일을 순서대로** 처리한다. 기준일이 last_processed_date 이하이면 아무것도 하지 않는다 (같은 날 중복 처리 방지). 테스트 추가.

## 4. 잘못 만들어진 상태 정리

- P3.1 실행으로 live DB에 생긴 CMCSA·FER 주문대기는 오래된 기준일로 만들어진 거라 무효야. live DB를 백업(`state_p31_backup.db`)하고 새로 시작해.
- 새 시작일은 위 1번 수정 후 확정되는 최신 기준일(9/22가 복구되면 9/22).

## 5. 완료 조건

- `pytest` 전부 통과
- `python -m engine.daily --no-send` 실행: 기준일이 최신 마감 거래일인지, 아니면 지연 모드로 신호 없이 끝나는지 확인
- 텔레그램은 이번엔 **보내지 마** (`--no-send`). 내가 결과를 보고 직접 보낼게.
