# P3.3 지시문 — 사라진 거래일 복구와 탐지

---

방금 진단 고마워. 원인이 명확해졌어: CSX·ODFL·PEP 캐시에서 2026-09-22 행이 **통째로 없어졌고**, 구멍 탐지는 NaN만 봐서 이걸 못 잡았어. 그 결과 9/22의 A1이 9/23으로 밀리거나(CSX·ODFL) 사라졌어(PEP). 아래를 처리해줘. 스케줄·드라이브는 여전히 만들지 마.

## 1. 누락 거래일 탐지 (거래일 달력 기준)

- `find_mid_series_gaps()`를 확장해서, P3.2에서 만든 미국 거래일 달력에 있는 날짜가 캐시 인덱스에 **아예 없는 경우**도 구멍으로 잡아줘 (NaN 행과 누락 행 둘 다).
- 탐지 범위는 지표 계산에 쓰는 전체 기간. 상장 전 기간은 제외.

## 2. 누락 거래일 복구

- 구멍이 있으면 그 날짜만 다시 받아서 채운다. 우선순위: 일봉 배열 종가 → 60분봉 그날 마지막 봉 종가(그날 고가·저가·시가·거래량은 60분봉에서 집계) → 실패.
- 채운 행에는 `close_source`(yahoo / hourly)를 남기고, 저가~고가 범위 검사는 그대로.
- 끝내 복구 못 한 종목은 `data_gap=True`로 신호 판정에서 제외하고 보고서 "데이터 상태"와 텔레그램에 표시.
- **캐시에서 행을 지우는 코드 경로를 전부 찾아서**, 한번 확정된 과거 봉은 새로 받은 데이터가 비어 있다는 이유로 지워지지 않게 막아줘. 이번에 9/22 행이 어떤 경로로 지워졌는지도 밝혀줘.

## 3. A1 판정 안전장치

- `check_a1`이 비교하는 "전날"이 실제로 **직전 거래일**인지 확인한다. 직전 행 날짜가 달력상 직전 거래일이 아니면 신호를 내지 않고 data_gap 경고로 처리.
- A2(10거래일), A1 만료, 재진입 대기(5거래일)처럼 거래일 수를 세는 곳도 행 개수가 아니라 달력 기준으로 세는지 점검해줘.

## 4. 테스트

- 캐시에 누락 행이 있을 때 탐지 → 복구 → 신호 날짜가 원래 날짜로 돌아오는지 (CSX 9/22 시나리오 재현)
- 복구 실패 시 신호 없음 + data_gap
- 새로 받은 데이터가 비어도 과거 확정 봉이 지워지지 않음
- 직전 행이 직전 거래일이 아니면 A1 없음

## 5. 캐시 전체 점검과 상태 재계산

- 101종목 전체 캐시를 점검해서 누락·NaN 거래일 목록을 표로 보여주고 복구해줘.
- live DB는 P3.2에서 9/23으로 시작하면서 잘못된 데이터로 CSX·ODFL 주문대기가 생겼어. `state_p32_backup.db`로 백업하고, 시작일 9/23으로 **복구된 데이터로 다시 처리**해줘.
