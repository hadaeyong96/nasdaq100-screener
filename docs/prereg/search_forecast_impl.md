# 검색량 실적 예고 — 구현 해석 (첫 잠금 전 고정)

> 규칙 원문: `docs/prereg/search_forecast.md`(태그 `search-forecast-prereg`). 이 문서는 원문에 숫자로 없는 부분을 첫 잠금 전에 고정한다.
> 코드: `core/search_forecast.py`(순수), `engine/search_forecast.py`(주간 실행), `store/search_forecast.py`(DB), `data/search_trends.py`(수집).

1. **대상**: 17개 회사. CHTR은 2026-11-01 나스닥 공식 구성 목록(api.nasdaq.com, 101종목)에 없어 시작 전 제외(`config/search_forecast.yaml` excluded).
2. **트렌드 라이브러리**: trendspy 0.1.6(버전 고정). pytrends는 GitHub 저장소가 보관(archived, 마지막 push 2024-08)돼 제외. trendspy는 보관되지 않았으나 마지막 커밋 2024-12. 설치 전 휠(sha256 74795fee…cbf)을 받아 소스를 읽음 — trends.google.com에만 요청, 하위 프로세스·eval·파일 쓰기 없음. 재시도·대기는 우리 코드가 맡는다(라이브러리 재시도 1회).
3. **수집**: 매 실행마다 검색어 하나씩 "today 5-y"(주간) 한 요청. 받은 값 전체를 수집 시각과 함께 그대로 저장(요청마다 0~100 기준이 달라 따로 둔다). 요청 간격 40초(v1.1, v1은 20초). 실패 = 30·60·120초 쉬고 다시(3회), 그래도 실패면 `search_fetch_log`에 기록만.
4. **점수에 쓰는 값**: 검색어마다 가장 최근 수집 한 번의 값만. YoY는 그 안에서만 계산(검색어끼리·요청끼리 섞지 않음).
5. **회계 분기**: EDGAR XBRL 매출 사실 중 기간 77~119일(12·16주 분기 포함)을 분기로, 4분기가 연간으로만 있으면 연간 − 누적(또는 세 분기). 다음 분기 끝 추정 = 4분기 전 끝 + 1년(최근 8개 분기 끝이 모두 달 말이면 12개월 뒤 달 말, 아니면 364일). 분기 시작 = 앞 분기 끝 + 1일. 추정한 끝으로 잠근 점수는 나중에 실제 끝이 달라도(53주 해 등, 최대 7일) 다시 계산하지 않는다.
6. **YoY·점수**: 분기 창 안 주(주 시작일 기준) 평균 ÷ 같은 창을 364일 앞으로 옮긴 평균 − 1. 창마다 주간 값 8개 미만이면 그 검색어는 뺀다. 회사 YoY = 검색어 YoY 중앙값(v1.1. v1 평균 방식은 `*_v1` 칸에 참고로 함께 잠금, 판정 제외). 기준 = 직전 8개 분기 회사 YoY 중앙값(같은 값으로). 점수 = 이번 분기 YoY − 기준.
7. **점수 시점**: 주간 실행(일요일)에서 분기 끝 + 10일이 지난 첫 실행에 계산(최대 6일 늦음). 시작 시즌 2026-Q4(분기 끝 2026-10-01 이후). 점수를 못 내면(검색량 부족) 잠그지 않고 다음 실행에 다시.
8. **잠금 두 단계**:
   - (가) 점수 잠금: 점수를 낸 실행에서 그 행들(회사·분기 끝·시즌·분기 시작·YoY·기준·점수·기준 수·계산 시각)을 해시해 잠금 파일에 한 줄.
   - (나) 시즌 예측 잠금: 시즌(분기 끝이 속한 달력 분기)의 17개 회사 점수가 다 모이거나, 시즌 끝 + 10일 + 7일이 지나면 모인 점수로 3등분(k = 회사 수 ÷ 3 내림, 상위 k = 매출 가속, 하위 k = 매출 감속, 나머지 예측 없음). 예측까지 넣은 행들을 해시해 한 줄. 이미 잠긴 시즌에 늦게 들어온 행은 "예측 없음"으로 잠금.
   - 이유: 회사마다 분기 끝이 달라(COST·ROST 등) 시즌 순위는 마지막 회사 점수가 나와야 정해진다. 그때까지 기다리면 일찍 발표하는 회사는 늘 무효가 되므로, 자기 검색량 점수는 분기 끝 + 10일에 먼저 잠근다.
9. **유효**: 기본 = 점수 잠금 시각(미 동부 날짜) < 실적 발표일. 같은 날은 무효. 시즌 예측 잠금 기준 유효도 `valid_pred_lock`으로 같이 기록한다(판정에 어느 쪽을 쓸지는 판정 전 사용자 결정).
10. **잠금 파일**: `docs/forecast_locks/YYYY-Qn.txt`에 잠금마다 한 줄 "UTC 시각 sha256=해시". 해시 = 잠근 행들을 키 정렬 JSON 한 줄씩 정렬해 이은 SHA-256. 같은 해시를 DB에도 둔다(나중에 대조). 종목·방향·점수는 공개 저장소에 쓰지 않는다.
11. **채점**: 실제 분기 = 잠근 분기 끝 ±20일의 EDGAR 분기. 발표일 = 분기 끝 뒤 100일 안 첫 8-K(항목 2.02) 또는 10-Q·10-K 공시일 중 이른 날. 매출 가속 정답 = 그 분기 매출 YoY(1년 전 ±20일 분기 대비) > 직전 분기 YoY. 주가: 발표일 또는 다음 거래일 = 위치 0, 위치 −1 종가 → +1·+21·+126 거래일 종가 수익률 − QQQ 같은 기간(yfinance Close). 기간이 안 찬 칸은 비워 두고 매주 다시 채운다.
12. **위키백과**: 회사·대표 제품 문서(config) 월간 조회수(user 접속, 완결된 달, 5년). 예비 자료 — 점수에 쓰지 않는다.
13. **실행**: `.github/workflows/search_forecast.yml` 일요일 KST 10:30(UTC 일요일 01:30), concurrency 그룹 `daily-screener`(v1.1. 편지·온도계와 같은 그룹, 대기만·취소 없음 — 가상 장부 DB 동시 쓰기 방지). 같은 가상 장부 DB를 받고 올린다. 잠금 파일은 봇이 main에 커밋·push.
14. **편지**: 월요일 개인판만 "검색량 예고: 잠금 n건 · 채점 m건 · 가속 적중 x%". n = 예측(가속·감속)이 잠긴 행, m = 매출 정답이 나온 행, x = 유효한 "매출 가속" 중 실제 가속 비율(없으면 —). 단체방판에는 없음. 집계 실패는 편지에 흔적을 남기지 않는다.
