# P2 작업 지시문 — 신호 판정 + 상태 전이 + 수량 계산

---

CLAUDE.md와 docs/strategy_v3.md의 4~8장, 11~12장을 먼저 읽고 P2 범위만 구현해줘.
P2 목표는 "매일 확정 봉 기준으로 종목별 단계를 관리하면서 매수·매도·손절 신호와 추천 수량을 뽑는 것"이야. 텔레그램 발송, 스케줄, 구글 드라이브 연동은 만들지 마 (P3~P4).

## 0. P1 마무리 3가지 (먼저 처리)

1. **일봉 종가 우선**: 캐시에 `close_source="meta"`로 저장된 값이 있어도, 새로 받은 일봉 배열에 그 날짜 종가가 들어 있으면 일봉 값을 쓰고 `close_source`를 지운다. 테스트로 확인.
2. **중간 종가 구멍 차단**: 마지막 봉이 아닌 곳에 close가 NaN인 날이 있으면 그 종목에 `data_gap=True`를 표시하고, 그날 신호 판정에서 제외하고, 실행 로그와 결과 파일에 크게 경고한다. 조용히 보간하거나 채우지 않는다.
3. **Invesco 출처 제거**: 구성 종목 출처 순서를 nasdaq_official → wikipedia → universe_fallback.csv로 정리.

## 1. 설정 추가 (config.yaml)

- `account.equity_usd`: 계좌 금액 (기본 100000, 사용자가 바꿀 값이라 주석으로 표시)
- `risk`: 단계별 위험 예산 A1 0.22%, A2 0.44%, A3 1.33%, B 1.00%, 갭 여유 1.5%, 최소 주당 위험 1%, 종목당 투입 한도 25%, 동시 보유 최대 8
- `entry.limit_markup`: 1.01 (매수 지정가 = 신호일 종가 × 1.01)
- `a3.mode`: breakout | pullback (기본 breakout), `a3.pullback_tolerance`: 0.5%
- `replay.lookback_days`: 60 (첫 실행 시 상태를 만들기 위해 되돌려 보는 거래일 수)
- 12장 가정값은 이미 있으면 그대로 쓴다.

## 2. core/ (모두 순수 함수)

### core/signals.py
- 정리본 4장(A1, A2, A3, B)과 5장(E1, E2, E3, 손절, A1 만료)의 조건을 날짜 하루 단위로 판정하는 함수들.
- 입력은 지표가 계산된 DataFrame과 그날 날짜, 종목 상태. 출력은 그날 발생한 이벤트 목록.
- **필요한 입력값이 NaN이면 그 신호는 "없음"** 으로 판정한다. 데이터 부족 플래그로 종목 전체를 막지 않는다 (SPCX처럼 구름은 없어도 A1·A2는 가능해야 함).
- A3는 `a3.mode`로 돌파형·되돌림형을 고를 수 있게 둘 다 구현한다.

### core/filters.py
- 7장 등급(S/A/B), 우선순위 점수(100점), 매매 금지 구간 6가지.
- 실적 발표 필터는 실적일을 입력으로 받는다. 실적일을 모르면(None) 신호를 막지 말고 `earnings_unknown=True`로 표시만 한다.

### core/sizing.py
- 6장 공식: 수량 = 내림(계좌 × 단계 위험 예산 ÷ 주당 위험), 주당 위험 = (매수가 − 손절가) + 매수가 × 갭 여유.
- 매수가는 지정가(종가 × 1.01), 주당 위험은 매수가의 1% 미만이면 1%로 올린다.
- 손절가: A1·A2는 A1 발생일 기준 swing_low, A3는 max(A1 기준 swing_low, 오늘 구름 하단), B는 진입일 swing_low.
- 종목당 투입 25% 한도, 동시 보유 8개 한도를 넘으면 수량을 줄이거나 신호를 "한도 초과"로 표시.

### core/state.py
- 8장 상태도 그대로: 대기, 정찰, 확인, 확정, 추세보유, 청산중.
- 하루 처리 순서: ① 손절 ② A1 만료 ③ E3 ④ E1·E2 ⑤ 진입 신호. 손절은 모든 신호보다 우선하고, 같은 날 손절이 나면 나머지는 무시한다.
- 이미 판 묶음의 E 신호는 무시, 청산중에는 추가 매수 없음, 대기 복귀 후 재진입 대기(5거래일) 적용.
- 중복 알림 방지 키(`sent_alerts`, 예: "A1:2026-09-10").
- 상태는 dict로 받고 새 dict를 반환한다 (원본 변경 금지).

## 3. data/earnings.py

- yfinance로 종목별 다음 실적 발표일을 받아 `data/cache/earnings.parquet`에 하루 단위로 캐시한다.
- 실패하거나 없으면 None. 전체 실행은 멈추지 않는다.

## 4. store/db.py (SQLite)

- 파일: `data/state.db` (.gitignore의 *.db로 이미 제외)
- 테이블 `positions`: 8장 "종목별 저장 항목" 전부 (ticker, name_kr, state, units, entries, stop, a1_date, cooldown_until, sent_alerts, updated_at). dict·list는 JSON 문자열로 저장.
- 테이블 `events`: 날짜, 티커, 이벤트 종류, 상세 JSON (나중에 브리핑·백테스트 검증용 기록)
- 테이블 `runs`: 실행 시각, 기준일, 종목 수, 경고 수

## 5. 체결 기록 입력 (data/fills.csv)

- 컬럼: date, ticker, unit(1/2/6/9), side(buy/sell), price, qty
- 헤더만 있는 빈 파일과 `data/fills.example.csv`(예시 2줄)를 만든다.
- 실행 때 fills.csv에 있는 기록이 추천 수량·진입가를 덮어쓴다. qty=0인 buy는 "체결 안 됨"으로 보고 그 묶음을 보유하지 않은 것으로 처리한다.
- 정찰 단계에서 A1이 체결 안 됨(qty=0)이면 쿨다운 없이 대기로 돌린다.
- 이 파일은 git에 올려도 되는지 판단이 필요하니, 일단 .gitignore에 넣고 예시 파일만 커밋한다.

## 6. engine/daily.py

- `python -m engine.daily` : 오늘 확정 기준일 하루를 처리
- `python -m engine.daily --replay` : state.db가 비어 있으면 최근 `replay.lookback_days` 거래일을 하루씩 되돌려 처리해 상태를 만든 뒤 오늘까지 진행 (추천 수량대로 체결됐다고 가정한 "가상 보유" 상태)
- `--dry-run` : DB에 쓰지 않고 결과만 출력
- 라이브 실행과 되돌려 보기는 **같은 core 함수**를 쓴다.
- 결과를 `outputs/signals_YYYY-MM-DD.md`와 `.csv`로 저장:
  - 신규 매수 신호 (단계, 등급, 점수, 지정가, 손절가, 추천 수량, 실적 확인 필요 여부)
  - 매도·손절 신호 (묶음, 수량, 사유)
  - 경고 (기준선 이탈, RSI 과열 해소, 목표 도달, data_gap, 실적일 확인불가)
  - 현재 단계별 종목 수 (대기/정찰/확인/확정/추세보유/청산중)
  - 점수 순 정렬

## 7. tests/

- 상태 전이 표 테스트: 정리본 8장의 모든 화살표를 합성 시나리오로 하나씩 검증
- 경계 사례: A1 후 10거래일째 A2는 유효, 11거래일째는 만료 / 손절과 E1이 같은 날이면 손절만 / E2가 E1보다 먼저 와도 묶음 2만 매도 / 청산중에 A3 조건이 와도 매수 없음 / 재진입 대기 중 A1 무시 / RSI 70 이상 골든크로스 B형 차단 / 20일 교차 4회 이상 A2 차단 / 실적 3거래일 이내 신규 매수 차단
- 수량 계산: 정리본 6장 계산 예시 표(갭 여유 0으로 설정 시 A1 37주, A2 49주, A3 148주)가 정확히 나오는지
- 신호 미래 데이터 방지: t까지 자른 데이터로 판정한 t일 이벤트 == 전체 데이터로 판정한 t일 이벤트
- 중복 알림: 같은 날 두 번 실행해도 이벤트가 한 번만 기록
- 모두 네트워크 없이
