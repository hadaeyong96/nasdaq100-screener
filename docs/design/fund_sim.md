## 1. 배경: 현재 시스템과 지금까지 알게 된 것

### 1.1 현재 시스템
| 항목 | 내용 |
|---|---|
| 대상 | 나스닥100 구성 종목 약 101개, 일봉 |
| 전략 | MACD 중심 + RSI 결합, 1:2:6 분할 매수(1차 정찰 · 2차 확인 · 3차 확정), 스윙 관점 (`docs/strategy_v3.md`) |
| 운영 | 자동매매 아님. 매일 GitHub Actions(KST 06:47)가 신호를 계산해 텔레그램으로 보내고, 사용자가 직접 판단해 주문 |
| 입력 | 구글 시트(계획·체결 탭) |
| 상태 저장 | 구글 드라이브의 SQLite(state.db, paper_state.db) |
| 모드 | live(사용자 실제 체결 기반 조언), paper(시스템 신호를 전부 따랐다고 가정한 가상 운영) |
| 코드 원칙 | `core/`는 순수 함수, 라이브와 백테스트가 같은 `core/` 함수를 사용, 미래 데이터 금지 테스트 필수 |

### 1.2 지금까지의 검증 결과 (2016~2021 백테스트, 사이징 버그 수정 후)
| 비교 | 결과 |
|---|---|
| 현 전략(B0.5) vs 무작위 진입 500회 | **백분위 0.0** (무작위 평균 +20.49%, 실제 +19.78%, 세후(a) 연복리) |
| 현 전략 vs QQQM 100% 매수후보유 | 세전은 +1.04%p 앞서지만, **세후는 -0.71~-1.91%p 뒤처짐** (잦은 매매의 양도세 부담) |
| 종목 부분 비중 | 평균 약 22% (나머지는 QQQM 대기 자금) |

**시사점**
1. 현재 종목 선택 규칙만으로는 무작위보다 낫다는 증거가 없다.
2. 세금·수수료를 반영하면 작은 우위는 쉽게 사라진다.
3. 새 설계는 "더 많은 전략을 시험"하는 것만으로는 부족하고, **다중 검정(많이 시도한 대가)을 반드시 차감**해야 한다.
4. 위 백테스트는 현재 구성종목으로 과거를 돌렸을 가능성이 높다(생존 편향). **QQQM 대비 비교는 전략에 유리하게 부풀려졌을 수 있다.** 🆕 v0.3에서는 F2에서 그 크기를 직접 잰다(5.8).

## 2. 목표와 원칙

### 2.1 목표
1. 여러 전략 계열을 **같은 조건**에서 가상 운용해 어떤 전략이 무작위·QQQM보다 나은지 검증한다.
2. 검증을 통과한 전략에만 가상 자금을 더 배분하는 **자본 배분 규칙**을 만든다.
3. 여러 **전략팀**이 동시에 고르는 종목을 **합의 추천**으로 보여 주고, 그 추천이 실제로 정보가 있는지 **추천 단위로 따로 검증**한다.
4. 각 층(배분·국면·진화)은 **단순한 대안보다 나을 때만** 켠다.

### 2.2 원칙 (변경 금지)
| 원칙 | 내용 |
|---|---|
| 가상 운용 | 시드 4,000만 원은 **가상**이다. 실제 주문은 지금처럼 사용자가 직접 판단한다. |
| 규칙 기반 직원 | 직원은 LLM이 아니라 **규칙 기반 봇**이다(3.6). |
| 같은 core 재사용 | 모든 전략은 기존 `core/` 지표·신호 함수를 재사용하고, 새 지표는 테스트와 함께 추가한다. |
| 미래 데이터 금지 | 모든 지표에 "t일까지 자른 데이터 결과 = 전체 데이터의 t일 값" 테스트를 적용한다. |
| 봉인 구간 | 2022-01-01 이후 데이터는 **최종 검증 때 딱 한 번만** 연다. |
| 비용 반영 | 수수료(매수·매도 각 0.07%), 환전 스프레드(0.1%), 해외주식 양도세(연 250만 원 공제 후 22%) |
| 설정 분리 | 근거가 약한 숫자는 `[가정]`으로 표시하고 `config.yaml`에서 읽는다. |
| 시점 유니버스 | 각 날짜의 유니버스는 **그날 실제 나스닥100 구성종목**이다. |
| 체결 가정 | t일 종가로 신호 계산 → **t+1일 시가 체결** + 슬리피지 0.05% `[가정]`. 거래마다 6개 필드 기록(5.2). |
| 배당 | 미국 배당 원천징수 15% 반영. 배당 재투자 여부를 설정에 명시. |
| 시도 기록 | 백테스트로 시험한 **모든 설정**(과거 v3 개발 중 시험분 포함)을 `store/trials.db`에 기록. 다중 검정의 N은 이 로그에서 나온다. |
| 사전 등록 | 봉인 구간을 열기 전 설정·코드·데이터 해시와 **판정 규칙(5.7)**을 부록 D에 기록하고 이후 바꾸지 않는다. |
| 🆕 단계적 도입 | 한 번에 한 층만 추가한다. 앞 단계가 검증되기 전에는 다음 층을 켜지 않는다(4.1). |

### 3.1 CEO: 자본 배분기 (Phase B부터 가동)

> [검토의견: v1.0 개선안] 초기에는 128개 직원을 밴딧의 팔로 두지 말고 8개 전략팀을 1차 팔로 둔다. 보상은 "초과수익 − 위험 벌점 − MDD 벌점 − 회전율 벌점"으로, 3·6·12개월 누적 성과를 함께 본다.

> [검토의견: Claude] **처리: 팀 단위는 수용, 보상식은 수정 수용.** 팀 단위 배분은 v0.2의 ①단계와 같으므로, ②단계(팀 내 상위 4명)를 떼어 내 **팀 안은 변형 균등**으로 단순화했습니다. 보상식은 그대로 쓰지 않습니다.
> 1. 벌점 가중치 3개가 **새 튜닝 대상**이 됩니다. 가중치를 결과를 보며 고르면 그것도 시도 횟수입니다.
> 2. 관측값인 초과수익에 **수수료·환전·슬리피지가 이미 빠져 있어** 회전율 벌점은 비용을 두 번 뺍니다. 다만 **양도세는 펀드 단위로 처리돼 직원 성과에 안 들어가 있으므로**, 회전율 벌점 대신 **예상 세금 부담**(실현이익 × 22% `[가정]`)만 차감합니다.
> 3. "위험 벌점"은 IR(초과수익 ÷ 변동성)이 이미 담당합니다. MDD는 v0.2처럼 **제약**으로 둡니다.
> 4. 3·6·12개월 누적은 겹치는 창이라 보상에 넣으면 자기상관이 생깁니다. **월간 성적표 보고용**으로 씁니다.

| 항목 | 설계 (v0.3) |
|---|---|
| 환경 | 전정보. 모든 직원의 가상 장부 성과를 매일 계산하므로 탐색 배분 불필요 |
| 선택지 | **8개 팀** (팀 안은 변형 균등 배분) |
| 관측값 | 팀별 **월간 초과수익**(QQQM 대비, 수수료·환전·슬리피지 반영) − 예상 세금 부담 |
| 추정 | 팀별 NIG(정규-역감마) 사후분포 → IR 표본 |
| 배분 | IR 표본 1,000회(시드 고정)에서 각 팀이 **최고일 사후확률** P → `팀 비중 = λ·P + (1−λ)·균등`, λ = 0.5 `[가정]` |
| 재배분 | 월 1회 `[가정]`. 1회 변동폭 팀당 ±10%p 이하 `[가정]` |
| 한도 | 팀당 최대 30%, 현금 최소 5% `[가정]` |
| 손실 제한 | 펀드 낙폭 -20% 도달 시 신규 배분 중단, QQQM 비중 확대 `[가정]`. 팀 가상 장부 낙폭 -25% 도달 시 해당 팀 배분 0(기록 유지) `[가정]` |
| 보고용 | 팀별 3·6·12개월 누적 초과수익, 최대 낙폭 |
| 이후 실험 | 팀 내 상위 k개 변형 선별(v0.2 방식). Phase B 통과 후 **별도 실험**으로만 |

### 3.2 국면 판정관

> [검토의견: v1.0 개선안] 초기 버전은 QQQ 종가와 200일 이동평균으로 Risk ON/OFF만 판정하고, VIX·기울기 추가는 별도 실험으로 검증한다. 국면 판정 규칙도 하나의 가설이므로 전략 최적화와 동시에 과도하게 조정하지 않는다.

> [검토의견: Claude] **처리: 수용.** v0.2는 CEO 의견을 받아 VXN 기준값, 252일 백분위, Fast-Track 3개 조건, 3일·5일 확인까지 **파라미터가 약 8개**였습니다. 학습 구간의 하락 국면은 2015~16년, 2018년 4분기, 2020년 3월 정도뿐이라 이 파라미터들을 믿을 만하게 정할 표본이 없습니다. v0.2의 4국면 설계는 버리지 않고 **실험 R2로 보존**합니다. CEO가 제안한 Fast-Track도 R2 안에서 검증됩니다.

**기본(R1): Risk ON / OFF**
| 국면 | 조건 |
|---|---|
| Risk ON | QQQ 종가 > 200일 이동평균 |

### 3.4 🆕 전략 · 변형 · 직원 계층 분리

> [검토의견: v1.0 개선안] Strategy / Variant / Employee를 데이터 구조상 분리하면 "MACD 전략이 좋은 것인지", "특정 RSI 값이 좋은 것인지"를 분리해 분석할 수 있다.

> [검토의견: Claude] **처리: 수용.** 이 분리는 다중 검정에도 필요합니다. `variants` 테이블이 곧 **시도 로그**의 뼈대가 되고, PBT가 만든 변형은 `parent_variant_id`로 계보가 남아 "세대수를 곱하는" 문제 없이 실효 N을 셀 수 있습니다.

| 계층 | 뜻 | 주요 필드 |
|---|---|---|
| Strategy | 전략 계열(팀) | strategy_id, 이름, 신호 함수 경로, 신호 유형 |
| Variant | 파라미터 조합 하나 (불변) | variant_id, strategy_id, params(JSON), params_hash, 생성 방식(LHS·수동·PBT), parent_variant_id, 생성일 |
| Employee | 지금 운용 중인 변형의 실행 주체 | employee_id, variant_id, 활동 시작·종료일, 배분 비중 이력 |

- 변형은 **한 번 만들면 바꾸지 않는다.** 파라미터가 바뀌면 새 변형이다.
- 분석 단위: 전략 효과 = 같은 전략 변형들의 평균, 파라미터 효과 = 전략 안 변형 간 차이.

### 3.5 직원 41명 + 대조군

> [검토의견: v1.0 개선안] 처음부터 128명을 운영하지 말고 8개 팀 × 4~6명, 총 40~60명으로 시작한다.

> [검토의견: Claude] **처리: 수용.** 팀7(QQQM)은 변형이 사실상 하나뿐이라 1명, 팀8은 파라미터가 2개라 4명으로 줄여 **41명**입니다. 직원이 줄면 시도 횟수 N이 줄어 다중 검정 차감도 작아지고, 계산 목표(30분)도 여유가 생깁니다.

- 팀 1~6은 **라틴 하이퍼큐브 샘플링**으로 6개 변형. 팀1의 변형 0은 **기존 B0.5 설정 그대로**(대조군 D와 같은 설정, 엔진 재현 확인용).
- 확대 조건: Phase A에서 어떤 팀의 변형 간 성과 편차가 커서 "파라미터 공간을 더 촘촘히 봐야 한다"는 근거가 나올 때만, 그 팀만 확대. 확대분도 시도 로그에 기록.
- 대조군은 5.6 참고.

### 3.6 왜 직원을 LLM으로 만들지 않는가
1. **정보 누출**: LLM은 학습 과정에서 과거 주가와 사건을 이미 보았다.
2. **재현성**: 같은 입력에 다른 답을 낼 수 있어 검증이 불가능하다.
3. **비용·속도**: 매일 수십 명 × 10년 호출은 감당되지 않는다.
- LLM은 **설명과 요약**(월간 성적표 문장 작성)에만 쓰는 것을 검토할 수 있다.

## 4. 학습 방식

### 4.1 🆕 단계적 도입 (Phase A → B → C)

> [검토의견: v1.0 개선안] CEO의 배분과 PBT가 동시에 작동하면 하나의 우연한 성공이 자본 배분과 복제·변이를 통해 함께 확대된다. Phase A(고정 전략 비교) → B(CEO 배분) → C(충분한 검증 후 PBT)로 단계적으로 도입한다.

> [검토의견: Claude] **처리: 수용 + 보강.** 빠진 점이 하나 있습니다. **봉인 구간은 한 번만 열 수 있으므로**, 봉인을 연 뒤에 도입하는 PBT는 과거 데이터로 검증할 방법이 없습니다. 그래서 PBT는 실제 펀드에 섞지 않고 **그림자 펀드(자본 없음)**로 paper 운영하면서, 고정된 펀드와 **24개월** `[가정]` 비교한 뒤에만 채택합니다.

| 단계 | 내용 | 어블레이션 | 데이터 |
|---|---|---|---|
| **Phase A** | 41명 고정 변형, 전 직원 균등, 진화·배분 없음. 국면은 보고용 | A0, A1 | 학습 구간(워크포워드) |
| **Phase B** | A + 팀 단위 CEO 배분. 이어서 국면 가중(R1, 필요 시 R2) | A2, A3, A4a, A4b | 학습 구간(워크포워드) |
| 🔒 **봉인 개봉** | Phase B 최종 구성 사전 등록 후 **1회** 검증 | — | 2022~현재 |
| **Phase C** | PBT를 **그림자 펀드**로 paper 운영. 실제 펀드는 봉인 검증 구성 그대로 유지 | A5 | 실시간 paper |

**PBT 채택 조건 (Phase C)**
- 그림자 펀드가 24개월 paper에서 고정 펀드보다 세후 IR이 높고, 그 차이가 두 펀드의 월간 성과 차이 기준 부트스트랩 90% 구간에서 0보다 클 때 `[가정]`.
- 조건을 만족하지 못하면 PBT는 도입하지 않는다(실패도 기록).

### 4.2 PBT 규칙 (Phase C 그림자 펀드 전용)
v0.2 규칙을 그대로 보존하되, 41명 규모에 맞게 조정.
| 단계 | 내용 |
|---|---|
| 평가 주기 | 반기 |
| 평가 창 | 최근 24개월. 신규 변형은 12개월 이상 쌓인 뒤 평가 `[가정]` |
| 적합도 | 국면 조정 적합도(4.3) |
| 퇴출 | 팀 안에서 "적합도가 팀 중앙값보다 낮을 사후확률 ≥ 90%" `[가정]`인 직원 중 **최대 1명** `[가정]` (팀당 6명 기준) |
| 엘리트 보존 | 팀 상위 2명은 변이 없이 유지 |
| 복제·변이 | 상위 2명 중 하나를 복제해 파라미터 ±10% `[가정]` 변경 → **새 Variant**(parent_variant_id 기록) |
| 교차 | 같은 팀 안에서만 |
| 고정 | 팀7·대조군은 제외 |

### 4.3 적합도 (Phase C 및 보고용)
```
국면 조정 IR = Σ_국면 ( 장기 국면 빈도 × 축소 추정된 국면별 IR )
적합도      = 국면 조정 IR − 예상 세금 부담의 IR 환산분
```
- 축소 추정: `국면별 IR = (n·국면 IR + n0·전체 IR) ÷ (n + n0)`, n0 = 120거래일 `[가정]`.
- 기본 국면은 R1(2국면). 최소 거래 30건 미만이면 평가 보류 `[가정]`.

### 4.4 합의 추천

| 항목 | 내용 |
|---|---|
| 팀 동의 | 팀 안 변형 중 **절반 이상** `[가정]`이 오늘 해당 종목 매수 신호 → 그 팀은 "동의" |
| 합의 점수 | **동의 팀 수 / 6** (1순위), 동의 직원 수(보조) |

| 표시 상태 | 예측력 검증(4.5) 전에는 **"참고용"** |

- 텔레그램 예시: `ODFL · 3/6 팀 합의(MACD·모멘텀·저변동) · 직원 11명`

### 5.3 🆕 성과 3계층

|---|---|---|---|
| 1. 전략 성과 | 변형 단위, 수수료·슬리피지 포함, 세전 | USD | 전략·파라미터 비교, CEO 입력 |
| 2. 포트폴리오 성과 | CEO 배분·대기 자금 포함, 세전 | USD | 배분 효과 판단(어블레이션) |
| 3. 투자자 시뮬레이션 | 환전·양도세·배당 원천세·**정수 주식**(user_capital 기준) | KRW | **최종 합격 판정** |

### 5.4 워크포워드
- 3년 학습 → 다음 1년 시험, 1년씩 이동 `[가정]`. 시험 연도 2018·2019·2020·2021 = **4개 창**.
- 창이 4개뿐이므로 창별 결과를 모두 보고하고 평균만으로 결론 내리지 않는다.

### 5.6 대조군 A~D

> [검토의견: v1.0 개선안] 대조군을 QQQM 매수후보유 / QQQM 정기 리밸런싱 / Random / 기존 B0.5 네 가지로 확대한다.

> [검토의견: Claude] **처리: 수용 + 정의 보강.** QQQM **한 종목만** 정기 리밸런싱하면 매수후보유와 똑같아서 비교 의미가 없습니다. 펀드는 현금 최소 5%를 들고 있으므로, B를 **"QQQM 95% + 현금 5%, 월 1회 리밸런싱"**으로 정의해 현금 보유의 효과를 분리합니다. Random은 v0.2의 **무작위 펀드 200회**(같은 파이프라인 통과)로 둡니다.

| 대조군 | 정의 | 확인하는 것 |
|---|---|---|
| A | QQQM 매수후보유 | 그냥 지수를 사는 것보다 나은가 |
| B | QQQM 95% + 현금 5%, 월 1회 리밸런싱 | 현금 보유·리밸런싱 효과를 뺀 성과 |
| C | 무작위 펀드 200회: 직원 신호만 같은 빈도·보유기간의 무작위 신호로 바꾸고 배분·국면까지 같은 파이프라인 통과 | 구조·분산·대기 자금 효과를 뺀 **실력** |
| D | 기존 B0.5 전략 (새 엔진으로 재실행) | 이번 업그레이드가 기존보다 나은가 |

### 5.7 합격 판정: PASS / FAIL / INCONCLUSIVE

> [검토의견: v1.0 개선안] PASS/FAIL에 INCONCLUSIVE를 추가하고, 수익률·MDD·샤프·소르티노·변동성·회전율·거래비용·시장 노출·종목 집중도·합의 추천 사후 성과를 검증한다.

> [검토의견: Claude] **처리: INCONCLUSIVE는 수용, 지표 목록은 수정 수용.** 10개 지표로 판정하면 그중 유리한 것만 골라 "합격"이라고 말할 여지가 생깁니다. **판정 지표 4개**를 사전 등록하고, 나머지는 **보고 지표**로 둡니다. INCONCLUSIVE도 해석 여지가 없도록 숫자로 정의했습니다.

**판정 지표 (계층 3 기준, 봉인 구간, 사전 등록)**
| # | 지표 | 기준 |
|---|---|---|
| J1 | 세후 연복리 수익률 | 대조군 A보다 높음 |
| J2 | 대조군 C(무작위 펀드) 분포 백분위 | 상위 10% |
| J3 | 최대 낙폭 | 대조군 A 이하 |
| J4 | 세후 IR | 어블레이션 A1(41명 균등 고정)보다 높음 |

**판정 규칙**
| 판정 | 조건 | 조치 |
|---|---|---|
| **PASS** | J1~J4 모두 충족 | paper 12개월 재확인 후 J1·J2 다시 충족 시 합의 추천 "정식" |
| **FAIL** | J2 백분위가 하위 50% **또는** J1이 대조군 A보다 연 1%p `[가정]` 넘게 뒤처짐 | 학습 결과를 실전 추천에 쓰지 않음. 결과 기록 |
| **INCONCLUSIVE** | PASS도 FAIL도 아님 (예: J2가 상위 10~50%), **또는** 데이터 품질 기준 미달(5.1), **또는** 봉인 구간 거래 수 < 100건 `[가정]` | 실전 추천에 쓰지 않음. paper 운영을 계속해 12개월마다 재판정. **봉인 구간을 다시 열어 설정을 바꾸는 것은 금지** |

**보고 지표 (판정에 쓰지 않음)**: 샤프, 소르티노, 변동성, 회전율, 거래비용 총액, 시장 노출(베타·평균 주식 비중), 종목 집중도(상위 5종목 비중), 합의 추천 IC, DSR(N_raw·N_eff).

### 5.8 🆕 엔진 검증: B0.5 재현
F2 완료 기준으로 새 엔진이 기존 결과를 재현하는지 확인한다.
1. **현재 구성종목 + 기존 체결 가정**으로 B0.5를 돌려 기존 +19.78%(세후(a))와 오차 0.1%p `[가정]` 안에서 일치 → 엔진 정확성 확인.
2. **시점별 구성종목**으로 바꿔 다시 돌림 → 차이 = **생존 편향의 크기**.
3. **t+1 시가 체결**로 바꿔 다시 돌림 → 차이 = **체결 가정의 영향**.
- 세 숫자를 모두 보고한다. 1.2의 결론이 얼마나 부풀려졌는지 처음으로 정량화된다.

### 5.9 다중 검정 보정
| 방법 | 용도 |
|---|---|
| 시도 로그 (`trials.db` = variants + 실험 실행 기록) | N_raw = 로그 전체 설정 수 (과거 v3 개발 시험분, 국면·배분 실험 포함) |
| 실효 N (N_eff) | 로그 전체 수익률 상관행렬에 ONC 군집 적용. PCA 고유값 추정과 함께 보고 |
| Deflated Sharpe Ratio | N_raw, N_eff 각각 계산, **보수적인 값 보고** |
| White's Reality Check / Hansen SPA | "최고 팀이 벤치마크보다 낫다"는 주장 검정 (Phase A 결과 보고) |
| 대조군 C 백분위 | **봉인 판정의 주 기준**(J2). 사전 등록된 단일 검정 |

- 🆕 41명 고정 + PBT 봉인 후 도입으로 **봉인 전 시도 수가 v0.2보다 크게 줄어** 차감이 작아진다. 이것이 단계적 도입의 통계적 이점이다.

| Deflated Sharpe | 여러 전략을 시도했을 때 운으로 좋아 보일 몫을 뺀 샤프 비율 |
| ONC 실효 N | 비슷한 전략끼리 묶어 "사실상 독립적인 시도 개수"를 세는 방법 |
| 무작위 펀드 | 직원 신호만 무작위로 바꾸고 나머지 구조는 똑같이 돌린 펀드 |
| 어블레이션 | 구성 요소를 하나씩 더하며 각각의 기여를 확인하는 검증 |
| 시점별 구성종목 | 과거 각 날짜에 실제로 지수에 포함돼 있던 종목 명단 |
| 사전 등록 | 결과를 보기 전에 검증 방법과 설정을 기록해 두고 바꾸지 않는 것 |
| 🆕 IC | 점수와 이후 수익률의 순위 상관. 추천이 정보를 주는지 재는 지표 |
| 🆕 INCONCLUSIVE | 성공·실패 어느 쪽으로도 판단할 증거가 부족한 상태 |
