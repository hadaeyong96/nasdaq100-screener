# 클로드 코드 지시문 — 오늘의 스크리닝 화면 + 매수 "왜?" 개선 (2026-10-06)

```
브랜치 feat/why-explain에서 작업한다(없으면 main 94bea29에서 만든다. 이미 있으면 이어서 한다). main 병합은 하지 않는다. .env 값은 출력하지 않는다.

전략 규칙은 docs/strategy_v3.md 1·2·4~8장을 따르고, 문서에 없는 규칙은 만들지 않는다.
승인 범위: core/explain.py, 새 순수 함수 모듈(core/screening_view.py 등), engine/daily.py(표시용 값 수집과 전달만), notify/report_html.py, notify/templates/report.html.j2, tests/, docs/design/.
신호·필터·상태 전이·수량·손절 계산(core/signals.py, filters.py, state.py, sizing.py)은 바꾸지 않는다. 텔레그램 브리핑(notify/briefing.py)도 바꾸지 않는다.

0. 먼저 확인하고 보고한다 (고치기 전)
- explain_buy에서 실제 값과 비교하지 않고 "y"로 고정된 체크(알려진 곳: B형 3개, A2 골든크로스)와, A3가 "종가" 자리에 ctx["limit"](지정가)를 쓰는 오류
- 차수별로 실제 적용되는 검사: ban_reasons 적용 차수, A1의 보유·쿨다운·실적 검사 여부, 재진입(B) 후보 정의
- 2차 후보 정의 확인: positions의 "정찰" 상태(1차 체결 확정, a1_date)만 A2 판정 대상인지(core/state.py _resolve_pending, process_day)
- 문서와 코드가 다른 점(예: 문서는 실적 3거래일 필터를 "전체"에 적용)은 고치지 말고 질문 목록으로 남긴다.

1. 보고서 맨 위 새 구역 "오늘의 스크리닝"
 1-1. 우리 전략 한눈에 (고정 카드, 문구는 템플릿 상수, 숫자는 config에서 읽음)
 - 이름: "바닥 반전 3단 확인 매수법 (1:2:6 피라미딩)"
 - 한 줄: 많이 떨어진 종목이 RSI → MACD → 일목 구름 순서로 반등을 증명할 때마다 1 → 2 → 6으로 늘려 산다. 떨어질 때 더 사는 물타기는 하지 않는다.
 - 뿌리: 후지모토 1:2:6(대본 MACD_11) + "맞을 때만 더 산다"(리버모어식 피라미딩). 유명 전략을 그대로 쓴 것이 아니라 대본을 모아 만든 우리 전략이라고 밝힌다.
 - 차수표: 차수 | 비중 | 사는 조건 | 뜻 | 손절 | 파는 신호 (1차·2차·3차·재진입). 기한·임계값(10거래일, 30/50/70, 갭 4% 등)은 config 값.
 - 공통 금지 구간 한 줄, 한 종목 최대 손실(config 값)
 - 윌리엄 오닐 CAN SLIM 비교표 4행: 사는 자리 / 종목 고르기 / 비중 늘리기 / 손절
 1-2. 오늘의 깔때기: 차수마다 레인 하나(색 구분), 위에 단계별 숫자 상자와 막대, 아래에 종목 표
 - 1차: 스캔 N → RSI 30 탈출 m → 검사 통과 k → 추천. 표: 순위·종목(한글명+티커)·RSI 어제→오늘·거래량 배수·구름두께·점수·결과(추천 / 제외 사유: 보유 중, 쿨다운, 실적 등 실제 검사만)
 - 2차: 1차 보유 종목 n → 오늘 골든크로스 m → 금지 구간 통과 k.
   · 2차 후보는 positions에서 "정찰" 상태(1차 체결 확정, a1_date 있음)인 종목이다.
   · 레인 위에 "1차 보유 명단" 표: 1차 매수일(a1_date)·종목·2차 기한(MM/DD). 마지막 줄은 "오늘 1차 추천 n종목 — 체결에 적으면 내일부터 포함".
   · 종목 표: 순위·종목·1차일(경과 거래일)·골든크로스 여부·RSI·등급·점수·결과(추천 / 제외 사유 / "대기 · 기한 MM/DD")
   · 최근 10거래일 events의 A1 신호 중 정찰 상태가 아닌 종목(사지 않음)은 "참고: 2차 대상 아님 n종목"으로 접어서만 보여 준다.
   · 대기 목록이 10줄을 넘으면 "n종목 더"로 접는다.
 - 3차: 2차 보유 n → 4조건과 갭 통과 k. 표: 종목·구름 위·앞구름 양운·후행스팬 돌파·MACD>시그널&RSI≥50·갭 값·점수·결과(추천 / "n/4 대기")
 - 재진입: 후보(0번 확인 정의) n → 골든크로스 m → 통과 k. 표: 순위·종목·정규화 MACD·RSI·등급·점수·결과
 - 제외·대기 종목 점수도 같은 priority_score로 계산해 표시한다(표시용). 순위는 추천 종목에만 매긴다.
 - 단계 숫자는 기존 _compute_funnel·브리핑 스크리닝 현황과 같은 정의를 쓴다. 다르면 이유를 보고한다.
 - paper 모드 보고서는 paper DB 기준으로 같은 방식을 쓴다.
 - 휴대폰 폭에서 페이지 가로 스크롤이 생기지 않게 하고, 표만 안에서 스크롤되게 한다.
 - 계산은 core/의 순수 함수로 만든다(입력: 지표 DataFrame들·상태·이벤트·config, 출력: 레인별 dict). 네트워크·파일·DB·현재 시각 접근 금지. DB 읽기는 engine에서 한다.

2. 매수 줄 "왜?" 설명 (core/explain.py)
- 출력에 sections를 추가한다: ① 우리 규칙 ② 왜 이 종목인가 ③ 어떻게 사나 ④ 다음 단계 + "근거: 전략 v3 4장 A1 · 대본 M11, M12" 형식. 기존 키(title, badge, checks, body, next)는 유지한다.
- ① 차수 조건마다 오늘 실제 값과 기준을 같이 보여 준다. ✓/✗는 값 비교로 정한다(고정 금지). 값이 없으면 "확인 불가".
  - A1: RSI 어제→오늘, 보유·쿨다운(실제 검사만)
  - A2: 1차 매수일, 경과 n/10거래일, MACD·시그널 값, RSI 30~70, 금지 구간(RSI 70, 20일 교차 n회, 실적), 등급과 기준
  - A3: 2차 보유, 종가 vs 구름 상단, 선행A vs 선행B, 종가 vs D일 전 고가(D는 config), MACD vs 시그널과 RSI, 갭, 진입 방식(config)
  - B: 구름, 양운, 후행스팬, 골든크로스, 정규화 MACD vs 기준, RSI 50~70, 금지 구간, 위험 예산(config)
- ② "오늘 101종목 → RSI 30 탈출 6 → 통과 4 → 점수 2위" 형식의 깔때기 문장과 점수 내역. 깔때기 구역과 같은 숫자를 쓴다.
- ③ 지정가 계산(종가 × 비율), A3 갭 보류 조건, 수량 계산식(계획금액 또는 기본 금액 × 차수 비율 ÷ (지정가 × 환율) = n주, 줄어든 이유), 손절가 기준과 최저가 날짜, 손절폭 %
- 쉬운 말 유지, 미래 데이터 금지

3. 테스트
- 깔때기 숫자 = _compute_funnel 숫자(같은 입력)
- 2차 표의 모든 종목 ⊂ 정찰 상태 종목, 안 산 A1 종목은 2차 표에 나오지 않음
- 차수별 ✓/✗가 값에 따라 바뀌는지, A3 종가 표시 회귀
- 동등성: 같은 고정 입력에서 매수·매도 신호, 수량, 손절가가 main과 완전히 같음
- 새 순수 함수의 미래 데이터 방지 테스트(t일까지 자른 결과 = 전체 데이터의 t일 결과)
- 전체 pytest를 네트워크 없이 통과

4. 견본

- 데스크톱과 휴대폰 폭(390px) 스크린숏을 outputs/에 저장한다(Playwright 사용 가능하면).

5. docs/design/screening_view.md에 설계를 적고, 커밋해서 feat/why-explain에 푸시한다.

완료 보고: 0번 확인 결과와 질문 목록, 변경 파일, 테스트 수, 동등성 결과, 깔때기 숫자 대조, 견본 파일과 스크린숏 경로, 1차 추천 종목 하나의 "왜?" 전문.
```
