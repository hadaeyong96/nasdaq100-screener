H4(과거 검증, moat_plan.md 4장)는 "탈락 아님" 판정을 받았을 때만 넘어가는 다음 단계다. 실제 돈을
움직이지 않고 모의 포트폴리오를 매월 평가만 한다 — 자동매매가 아니다.

## 1. 공통 규칙

| 항목 | 규칙 |
|---|---|
| 판단 기준일 | 2026-09-30. 이 날짜까지 filed된 공시만 등급·비중 계산에 쓴다(미래 데이터 금지) |
| 진입 | 다음 거래일(2026-10-01) 시가 + 슬리피지 0.05%(`config.yaml backtest.costs.slippage_pct`). 실행 시점에 아직 이 가격이 없으면(당일 미확정 봉) 그 종목은 "진입 대기"로 저장하고, 다음 실행 때 값이 생기면 채운다 |
| 유니버스 | 기준일(2026-09-30)의 나스닥100 구성종목(시점별 명단, `data/universe_history.py`) |
| 교체 | 매년 4월 첫 거래일(`config.yaml moat.rebalance_month` = 4). 첫 교체는 2027-04. 그 사이 보유 종목·비중 변경 없음(지수에서 빠져도 다음 교체일까지 보유) |
| 등급 재계산 | 매월 실행 시 M1~M5·등급을 다시 계산해 **기록만** 한다. 보유 종목·비중은 바꾸지 않는다(교체일 전까지) |
| 비용·세금 | H4와 동일 — 매수·매도 수수료 각 0.07%, 환전 스프레드 0.1%(최초 1회만, moat_backtest.py 모듈 docstring 참고), 양도세(연 250만 원 공제 후 22%), 배당 원천세 15%(`config.yaml backtest.costs`, `backtest.tax`) |
| 업종 분류 | yfinance 현재 분류(H4와 같은 한계 — 과거 시점 분류와 다를 수 있음) |
| 봉인 | paper 코드는 2026-10-01 이전 가격을 절대 읽지 않는다(아래 "봉인 규칙" 참고). 이건 과거 검증(H4)의 `core/seal.py` 봉인과는 별개의, paper 전용 하한선이다 |

## 2. P1 — 넓음 전부, 동일 비중

- 편입: 기준일 등급이 "넓음"인 전 종목
- 비중: 동일 비중, 업종 최대 30%(`config.yaml moat.sector_cap_pct`). 초과분은 비례 배분
- 구현: `core/moat_backtest.allocate_equal_weight_with_sector_cap`을 그대로 재사용(수정 금지)

## 3. P2 — 새 가설 H4b: 넓음 전부, 시가총액 비중

- 편입: P1과 동일(기준일 "넓음" 등급 전 종목)
- 비중: 기준일 시가총액 비중. 업종 최대 30%, **종목 최대 10%** 동시 적용(초과분은 제한에 걸리지
  않은 종목에 비례 재배분 — `allocate_equal_weight_with_sector_cap`과 같은 water-filling 방식이지만
  시작값이 동일 비중이 아니라 시가총액 비중이고 캡이 두 종류라 새 함수로 구현한다, `core/moat_paper.py`.
  기존 `core/moat_backtest.py`는 이 계산에 가져다 쓰지 않는다)

**시가총액 계산 (2026-10-01 사용자 지시로 확정)**

시가총액 = 유통주식수 × 진입가(2026-10-01 시가, 위 "진입" 규칙과 동일). **2026-09-30 종가가
아니라 진입가를 쓴다** — 봉인 구간(2026-10-01 이전) 가격을 아예 읽지 않기 위해서다. 진입가가
아직 없으면("진입 대기") P2 비중도 "진입 대기"로 두고 다음 실행 때 계산한다.

유통주식수는 아래 우선순위로 구한다(종목마다 실제로 어떤 출처를 썼는지 `docs/paper/moat_paper_start.json`에 기록):

1. SEC EDGAR `dei:EntityCommonStockSharesOutstanding` — 2026-09-30까지 filed된 공시 중 가장 최근 값
   (표지(cover page) 공시 주식 수). 주식 종류가 여러 개인 회사(예: GOOGL/GOOGL, GOOG)는 **모든
   종류를 합산하고 회사 단위로 한 번만 센다**(나스닥100 유니버스에서 같은 회사의 복수 종목군은
   `scripts/moat_report.dedupe_rows_by_cik`로 이미 CIK 기준 중복 제거하는 것과 같은 원칙).
2. 1번이 없으면: 가장 최근 분기 `us-gaap:WeightedAverageNumberOfDilutedSharesOutstanding`
   (`core/moat.py`의 `diluted_shares` 태그 후보, M5 지표가 이미 쓰는 것과 같은 시계열 재사용)
3. 2번도 없으면: yfinance `sharesOutstanding`(현재 조회 시점 값이라 기준일과 시점이 다를 수 있음 —
   이 경우만 "출처: yfinance(시점 다름)"로 명시 표시)

## 4. 비교 대상

- QQQM 매수 후 보유 (대조군)
- QQEW 매수 후 보유 (참고용 — 동일가중 나스닥100 ETF)
- 무작위 포트폴리오 1,000개(`config.yaml moat.random_trials` = 1000, 시드
  `moat.random_seed` = 20261001). P1과 같은 종목 수(기준일 "넓음" 종목 수)·같은 업종 제한(30%)·
  동일 비중으로, 기준일 나스닥100 전체 유니버스에서 추출(H4와 같은 방식 —
  `core/moat_backtest.draw_random_portfolio` + `allocate_equal_weight_with_sector_cap`).
  재현을 위해 유니버스 명단·업종 매핑·시드·종목 수만 시작 파일에 저장하고, 평가 시점마다 같은
  시드로 다시 뽑는다(1,000개 구성 전체를 매번 저장하지 않음 — 결정적 재현이라 저장할 필요가 없음)

## 5. 판정 (2028-10, 24개월 뒤)

- **P1**: 세후 수익률이 QQQM을 넘고, 무작위 1,000개 대비 백분위 상위 25% 이상 → 통과
- **P2**: 세후 수익률이 QQQM을 넘으면 → 12개월 추가 관찰(2029-10까지 연장). 못 넘으면 그 시점에 종료
- QQEW·좁음 이상·없음 비교는 참고 보고용이며 판정에 쓰지 않는다(H4와 같은 원칙)

## 6. 봉인 규칙 (paper 전용)

`core/moat_paper.py`의 가격 조회 함수는 요청 날짜가 2026-10-01보다 이른 경우 예외를 낸다(코드로
강제, 테스트로 확인 — P1.4). 이는 과거 검증(H4)이 쓰는 `core/seal.py`의 `seal_date`(2022-01-01)
봉인과는 별개다. paper는 애초에 과거 가격을 쓸 이유가 없으므로(진입일 자체가 2026-10-01), 이
하한선은 설계 원칙을 코드로 재확인하는 안전장치다.
