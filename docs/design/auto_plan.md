# 계획 탭 자동 기록 v2 (L3/B4)

> 작성 2026-10-02 · 브랜치 `feat/auto-plan` · 관련: docs/design/live_advisor.md(계획·체결 시트)
> v1(신호일에 계획 줄 쓰기) → v2(추천은 기본 금액으로 수량 표시, 계획 줄은 실제로 산 뒤에 만듦)

## 0. v2로 바꾸는 이유

사용자는 추천을 보고 종목을 고른 뒤 산다. v1은 계획 줄이 있어야 수량이 나와서, 추천 시점에는 수량이
0이었다(예: ROP). v2는 투자현황 탭의 "종목당 계획금액"으로 모든 추천에 수량을 붙이고, 계획 줄은 실제로
산 뒤에 만든다.

## 1. 흐름

매일 실행(live) → 계획·체결·투자현황 탭 읽기 → 첫 매수 후 계획 줄이 없는 종목에 계획 줄 추가(D) →
그 줄을 메모리 계획에 합침 → 판정·추천 수량 계산(계획 있으면 계획 기준, 없으면 기본 금액 B) →
남은 현금 경고(C) → 브리핑 발송. 체결 탭은 사용자가 직접 기록한다(이 기능은 읽기만).

## 2. v2 규칙

### A. 투자현황 탭 읽기 (읽기만)

- 탭 이름 "투자현황". A열 항목 이름으로 행을 찾고 B열 값을 읽음 (괄호·공백 무시, 쉼표 있는 숫자 허용)
  - "총 투자금" → `total_krw`
  - "종목당 계획금액" → `per_ticker_budget_krw`
- 탭이 없거나 칸이 비면 오류로 멈추지 말고 None + 보고서 경고 한 줄
  ("투자현황 탭에 종목당 계획금액이 없어 기본 수량을 계산하지 않았습니다"). 이때는 지금처럼 계획 없는 종목 수량 0

### B. 추천 수량 (시트에 쓰지 않음, 메모리 계산만)

- live 모드 매수 추천 줄마다: 계획 탭에 그 티커가 있으면 기존대로 그 계획금액·기준가 사용
- 없으면 `per_ticker_budget_krw`로 `core.sizing.plan_tranche_qty`(기준가 없음 방식, 오늘 지정가) 계산, 비고에 "기본 금액" 표시
- 이 기본 금액 종목은 계획·체결 판정 표(보유 현황 탭)의 대상에 넣지 않음 (매수 추천 표에서만 사용)

### C. 남은 현금 경고

- 투자 원금 = 체결 탭의 (매수 수량×체결가×환율) − (매도 수량×체결가×환율), 대기자금(QQQM) 줄 제외. 환율 빈칸은 기존 채우기 값 사용
- 남은 현금 = `total_krw` − 투자 원금
- 오늘 추천 투입금액 합계가 남은 현금보다 크면 보고서 경고 한 줄, 한 줄의 투입금액이 남은 현금보다 크면 그 줄 비고에 "현금 부족"
- `total_krw`가 없으면 경고 생략

### D. 계획 줄 자동 생성 시점 변경 (신호일 → 첫 매수 다음 실행)

- 대상: 체결 탭에 매수 기록이 있고, 보유 수량 > 0이고, 계획 탭에 티커가 없는 종목 (대기자금 줄 제외)
- 쓰는 값: 티커, 계획금액 = `per_ticker_budget_krw`, 등록일 = 그 종목의 첫 매수일, 기준가 = 첫 매수 체결가,
  메모 = "자동 추가 · 첫 매수 YYYY-MM-DD"
- `per_ticker_budget_krw`가 없으면 쓰지 않고 경고
- 같은 실행에서 쓴 줄은 메모리 계획에 합쳐 오늘 판정·수량에 바로 반영

### E. v1에서 없애는 것

- 신호일에 계획 줄 쓰기, 하루 최대 개수(`max_new_per_day`), 만료 메모 기능 → 코드·테스트·config 항목 삭제
- config `live.auto_plan.default_budget_krw` 삭제 (투자현황 탭 값만 사용)

### F. v1에서 그대로 두는 것

- 입력 칸 5개(티커, 계획금액, 등록일, 기준가, 메모)만 쓰기, 수식 칸 절대 안 씀
- 입력 칸 5개가 모두 빈 첫 줄에 씀
- 기존 계획 줄은 절대 고치거나 지우지 않음
- 쓰기는 계획 탭만 (투자현황·체결 탭 쓰기 시도 시 오류)
- 쓰기 실패해도 브리핑 진행 + 경고
- paper 모드 쓰기 없음, dry-run 쓰기 없음, `enabled: false`면 지금과 같은 동작

## 3. 구현 결정(문서에 없던 세부)

- 열은 머리글 이름으로 찾는다(`data/fills.py`의 `_normalize_header` 재사용 — 괄호 설명·공백 무시, 열 순서가 바뀌어도 작동).
  `append_row`는 쓰지 않는다(1000행까지 수식이 미리 채워져 있음) — 빈 줄의 입력 칸 5개만 셀 단위로 업데이트
- "티커가 없는 종목" 판정은 계획 DataFrame(유효한 줄)과, 쓰기 직전 시트 원본의 티커 칸 전체를 둘 다 본다 —
  계획금액 오류 등으로 DataFrame에서 빠진 줄의 티커도 중복 추가하지 않는다
- 첫 매수일이 같은 매수가 여럿이면 체결 탭에서 먼저 적힌 줄의 체결가를 기준가로 쓴다
- 투자 원금 계산에서 환율 채우기 값까지 없는 체결 줄은 빼고, 뺀 건수를 경고에 적는다
- 시트가 아닌 로컬 fills.xlsx 폴백(인증 정보 없음)일 때는 투자현황 탭이 없으므로 v2 기능 전체(B·C·D)를 쓰지 않는다
- `--dry-run`이면 시트에 쓰지 않고 메모리 병합만 한다(보고서 수량은 그대로 보임)
- `enabled: false`면 투자현황 탭도 읽지 않는다

## 4. 구조

- `core/auto_plan.py`(순수 함수): 순보유 수량, 첫 매수 계획 줄 고르기, 투자 원금, 남은 현금 판정, 메모리 계획 병합
- `data/sheets.py`: 투자현황 탭 읽기(`read_portfolio`), 계획 탭 쓰기(머리글로 열 찾기, 빈 줄 찾기, 셀 단위 업데이트)
- `engine/daily.py`: live에서 투자현황 읽기 → 첫 매수 계획 줄 쓰기·메모리 병합 → 판정 → 추천 수량(기본 금액) → 남은 현금 경고
- `config.yaml`: `live.auto_plan.enabled`만 남김

## 5. 시험

가짜 시트 클라이언트 테스트까지만 한다. 실제 시트 쓰기 시험은 사본 시트로 따로 한다.
