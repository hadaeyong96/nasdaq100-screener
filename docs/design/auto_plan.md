# 계획 탭 자동 기록 (L3/B4)

> 작성 2026-10-02 · 브랜치 `feat/auto-plan` · 관련: docs/design/live_advisor.md(계획·체결 시트)

## 1. 흐름

매일 실행(live) → 오늘 매수 신호 계산 → 계획 탭에 티커가 없는 종목만 새 줄 추가 → 같은 실행에서
그 계획을 메모리에 합쳐 수량 계산 → 오늘 보고서에 바로 수량 표시 → 브리핑 발송.
체결 탭은 사용자가 직접 기록한다(이 기능은 읽기만).

## 2. 규칙

| 항목 | 규칙 |
|---|---|
| 대상 | 오늘 진입 신호(A1·A2·A3·B) 종목 중 계획 탭에 티커가 없는 종목. 하루 최대 `live.auto_plan.max_new_per_day`(기본 5), 점수 높은 순(같은 점수는 티커 오름차순) |
| 쓰는 칸 | 티커, 계획금액, 등록일, 기준가, 메모 — 이 5개만. 열은 머리글 이름으로 찾는다(`data/fills.py`의 `_normalize_header` 재사용 — 괄호 설명·공백 무시, 열 순서가 바뀌어도 작동) |
| 수식 칸 | 환율, 1차~남은(주) 등 위 5개 외 모든 열은 절대 쓰지 않는다 |
| 쓰는 위치 | 티커 칸이 비어 있는 첫 줄. 그 줄의 5개 입력 칸만 셀 단위로 업데이트한다(`append_row` 금지 — 1000행까지 수식이 미리 채워져 있음) |
| 계획금액 | `live.auto_plan.default_budget_krw`(기본 3,000,000) |
| 기준가 | 오늘 신호의 지정가 |
| 등록일 | 실행일(KST) `YYYY-MM-DD` |
| 메모 | `자동 추가 YYYY-MM-DD · {차수 표시 이름} · 손절 ${손절가:.2f}` (차수 표시 이름: 1차 정찰·2차 확인·3차 확정·재진입) |
| 기존 줄 | 절대 고치거나 지우지 않는다. 예외는 아래 만료 메모 하나 |
| paper 모드 | 쓰지 않는다 |
| 쓰기 실패 | 예외를 잡아 보고서 경고에 `계획 자동 기록 실패: 사유`를 표시하고 브리핑은 그대로 진행. 실패해도 오늘 보고서 수량은 메모리 계획으로 계산 |
| 끄기 | `live.auto_plan.enabled: false`면 지금과 완전히 같은 동작(시트 쓰기 0번) |
| 권한 | `data/sheets.py` `_SCOPES`의 `spreadsheets.readonly` → `spreadsheets` (`drive.readonly`는 그대로) |
| 보안 | 인증 정보 값은 출력·로그하지 않는다 |
| 쓰기 대상 탭 | 계획 탭만. 다른 탭에 쓰기를 시도하면 코드에서 오류를 낸다 |

### 만료 메모 (2026-10-02 사용자 결정: 기간 기준)

원안("보유 0주 + 그 종목의 1차 신호가 만료(A1_EXPIRE)")은 지금 코드에서 동시에 성립할 수 없다 —
`core/state.py`는 1차를 보유했을 때만 A1_EXPIRE 이벤트를 내고, 안 산 A1 신호는 다음 날 UNFILLED로
대기 상태로 돌아간다. 그래서 같은 기간 값으로 판정한다:

- 조건(모두 충족): ① 메모가 자동 추가 원문 그대로(`자동 추가 YYYY-MM-DD · 1차 정찰 · 손절 $X.XX`와
  정확히 일치 — 사용자가 한 글자라도 바꿨으면 안 함), ② 체결 탭 기준 보유 0주, ③ 메모의 등록일부터
  오늘 기준일까지 그 종목 거래일 수가 `assumptions.a1_to_a2_expiry_days` 이상
  (`core.signals.check_a1_expired`와 같은 판정)
- 동작: 메모 끝에 ` · 만료 YYYY-MM-DD`(실행일 KST)를 한 번만 덧붙인다(덧붙인 뒤에는 ①이 깨져 다시 안 붙음)
- 쓰기 직전 시트의 메모를 다시 읽어 판정 때 값과 같을 때만 그 칸 하나를 업데이트한다

## 3. 구현 결정(문서에 없던 세부)

- 손절가가 없는 신호(매수 보류)는 메모를 만들 수 없어 추가 대상에서 뺀다
- 한 종목에 같은 날 신호가 여럿이면 점수가 가장 높은 하나만 쓴다
- "티커가 없는 종목" 판정은 계획 DataFrame(유효한 줄)과, 쓰기 직전 시트 원본의 티커 칸 전체를 둘 다
  본다 — 계획금액 오류 등으로 DataFrame에서 빠진 줄의 티커도 중복 추가하지 않는다
- 빈 줄 판정: 티커 칸이 비어 있고 나머지 4개 입력 칸도 비어 있는 첫 줄(입력 칸에 사용자 값이 남은 줄은
  덮어쓰지 않으려고 건너뜀)
- 시트가 아닌 로컬 fills.xlsx 폴백(인증 정보 없음)일 때는 자동 기록을 하지 않는다
- `--dry-run`이면 시트에 쓰지 않고 메모리 병합만 한다(보고서 수량은 그대로 보임)

## 4. 구조

- `core/auto_plan.py`(순수 함수): 추가할 줄 고르기, 메모 만들기, 만료 메모 판정, 메모리 계획 병합
- `data/sheets.py`: 계획 탭 쓰기(머리글로 열 찾기, 빈 줄 찾기, 셀 단위 업데이트, 만료 메모 덧붙이기)
- `engine/daily.py`: live에서 신호 계산 뒤 → 추가할 줄 선택 → 시트 쓰기 → 계획 메모리 병합 → 기존 사이징
- `config.yaml`: `live.auto_plan` (enabled: true, default_budget_krw: 3000000, max_new_per_day: 5)
