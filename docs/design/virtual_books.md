# 가상 장부 5개 (관찰 전용)

실제 돈은 QQQM만 굴린다. 레버리지 ETF는 가상 장부로만 매일 관찰한다. 실제 주문 기능은 없다.

## 장부

| 장부 | 규칙 |
| --- | --- |
| QQQ 그냥 보유 | 시작일 종가에 전액 QQQ |
| QLD 그냥 보유 | 시작일 종가에 전액 QLD |
| TQQQ 그냥 보유 | 시작일 종가에 전액 TQQQ |
| QLD 200일선 전환 | QQQ 종가 > 200일 단순이동평균이면 QLD, 같거나 아래면 SGOV |
| TQQQ 200일선 전환 | 같은 신호로 TQQQ 또는 SGOV |

- 각 가상 1억 원, 같은 날 시작. 시작일 원/달러 종가로 달러 환산, 이후 달러 운용.
- 신호: t일 QQQ 종가 vs 200일 SMA → t+1 거래일 종가 체결 (sealed-a B1과 같은 방식, `core.l1b.above_sma`).
  시작일 첫 매수는 시작일 전 거래일 신호로 정한다.
- 체결: 정수 주식, 수수료 편도 0.07%, 슬리피지 0. 운용보수는 ETF 가격에 반영돼 따로 빼지 않는다.
- 분배금 (2026-10-14 사용자 확정): 원천징수 15% 뒤 배당락일 현금으로 쌓는다(재투자 안 함).
  분할 반영 종가는 분배금을 빼고 움직이므로, 이걸 빼면 SGOV 수익이 거의 0으로 보인다.
- 세금 (sealed-a와 같음, 2026-10-14 사용자 확정): 연말(그해 마지막 거래일, 전환 체결 뒤) 실현 순이익 × 22%,
  공제·이월결손 무시, 달러 기준. 장부 현금에서 실제로 뺀다 — 현금이 모자라면 보유 종목을 정수 주식으로
  팔아 내고(매도기록 사유 "세금 납부 매도", 전환 횟수에는 안 셈), 그 매도 손익은 다음 해 장부로 넘긴다.
  모든 장부에 "청산 가정 세후 추정"
  (오늘 종가 전량 매도·매도 수수료 포함, 올해 실현 + 미실현 이익 × 22%)을 같이 낸다.
- 설정값은 모두 `config.yaml` `virtual_books`.

## 실행·저장

- `engine/daily.py` live 실행 뒤, 브리핑을 만들기 전에 `engine.virtual_books.run_safely`를 부른다.
  장부는 매번 시작일부터 다시 계산한다(순수 함수 `core/virtual_books.py`).
- DB: `data/virtual_books.db` (live·paper DB와 분리). Actions에서는 드라이브 state 폴더의
  `virtual_books.db`를 `scripts/drive_sync.py --mode vbooks`로 받고 올린다(`GOOGLE_DRIVE_STATE_FILE_ID_VBOOKS`).
- 같은 날 두 번 실행: 일별·체결 표는 통째로 바꿔 쓰고, 실행 기록(runs)은 run_id·기준일로 남긴다.
  알림은 alerts 표에 (종류, 키)로 실제로 보낸 뒤에만 기록해 한 번만 보낸다.
- 오류 격리: 장부 오류는 잡아서 운영 알림만 따로 보낸다 — 기존 브리핑은 그대로 나간다.
  시트 기록만 실패하면 장부·국면 줄은 정상, 부분 오류 알림만 보낸다.
  워크플로의 vbooks 동기화 스텝은 `continue-on-error`.

## 운영 시작 절차 (시작일·환율 고정)

1. 시작일은 **2026-10-14로 고정**했다(`start_date: "2026-10-14"`, 2026-10-15 사용자 결정 — 원래 계획
   "첫 기록 = 10/15 예약 실행"의 기준일). 10/15 첫 예약 실행이 10-14 종가 빈 행으로 실패해(아래 "빈 종가")
   첫 성공 실행 날짜로 시작일이 밀리지 않게 먼저 고정한 것이다.
   시작 환율(`start_fx: null`)은 첫 성공 실행 때 10-14 원/달러 종가(KRW=X)로 정해져 드라이브
   `virtual_books.db`의 meta에 저장된다 — 2번 절차로 config에 옮겨 고정한다(고정 커밋은 사용자 승인 후).
2. 첫 실행 뒤 시트 전략요약 탭의 **"config 고정값"** 줄(예: `start_date: "2026-10-15"  start_fx: 1334.1300048828125`)을
   그대로 `config.yaml` `virtual_books.start_date`·`start_fx`에 옮겨 적고 커밋한다(환율은 반올림하지 말 것 —
   반올림하면 시작 달러 금액이 아주 조금 달라진다).
3. 고정한 뒤에는 DB가 사라져도 같은 장부가 다시 계산된다(장부는 매번 시작일부터 다시 계산).
   설정 시작일과 DB 기억값이 다르면 설정값을 쓰고 경고를 남긴다.
4. 사본 시트로 며칠 운영한 뒤 실제 시트로 바꿀 때는 Secret `VIRTUAL_BOOKS_SHEETS_ID`만 바꾼다
   (세 탭은 없으면 새로 만든다, 다른 탭은 건드리지 않는다).

## 빈 종가 (2026-10-15 수정)

마감 직후(예약 실행은 보통 KST 09시 전후 = 미국 동부 20시쯤) yfinance가 그날 행을 종가 없이 주는 일이 있다.
`data/virtual_books_data.py`는 **맨 끝에서부터 종가가 하나라도 빈 날**을 잘라내고 경고를 남긴다
(`[virtual_books] 경고: 맨 끝 종가가 빈 날 …`). 장부는 매 실행 시작일부터 다시 계산하므로 다음 실행에서 따라잡는다.
그날은 장부 기준일이 브리핑 기준일보다 하루 앞이라 브리핑 국면 줄은 빠진다.
**중간 날짜**가 비면 채우지 않고 지금처럼 멈춘다(오류 알림). 시작일 당일이 잘리면 "시작 전"으로 처리한다.

## 시트 (`VIRTUAL_BOOKS_SHEETS_ID`, 먼저 사본 시트)

`data/virtual_books_sheet.py`는 아래 세 탭만 쓸 수 있다(다른 탭은 코드로 막음). 매 실행 통째로 다시 쓴다.

- 전략비교_일일: 날짜, QQQ 종가·200일선·국면·전환 장부 보유, 다섯 장부 총자산($)·누적(%)·QQQ 대비(%p)·낙폭(%)
- 매매기록: 장부, 신호일, 체결일, 구분, 종목, 수량, 가격, 수수료, 실현손익, 사유
- 전략요약: 누적 수익, 연환산(60일 미만 비움), 최대 낙폭, 전환 횟수, 세후 값 + 시작 조건·가정

## 브리핑·알림

- 제목 바로 아래 한 줄(첨부 설명·HTML 보고서 맨 위에도): `오늘 국면: QQQ 200일선 위(+x.x%) · 전환 장부 QLD·TQQQ 보유 중`.
  오늘이 전환 신호일이면 `→ 오늘 전환 신호, 다음 거래일 종가에 SGOV로`를 덧붙인다.
- 200일선 전환 신호일: 개인 채팅에 알림 한 통(최근 5거래일 안의 미발송 신호만).
- TQQQ 그냥 보유 낙폭이 처음 −50% 이하가 된 날: 한 번만 알림.
