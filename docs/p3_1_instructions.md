# P3.1 보완 지시문 — 미체결 처리와 표시 정리

---

P3 완료 보고를 검토했어. 판단 2, 3은 그대로 채택이야. 아래를 보완해줘. 스케줄·드라이브는 여전히 만들지 마.

## 1. 체결 전 단계의 상태 (최우선)

live 모드인데 보유 0인 상태에서 "정찰 3 · 추세보유 1"로 집계되고 있어. 체결 기록이 없는 종목이 정찰·추세보유로 남으면, 사지 않은 종목에 내일 2차 신호나 매도 신호가 나갈 수 있어.

- 매수 신호를 낸 날의 종목은 새 상태 `주문대기`로 둔다. 단계별 종목 수에도 `주문대기`로 따로 집계.
- 다음 실행 때 그 신호에 대한 체결 기록이 있으면 → 원래 단계(정찰·확인·확정·추세보유)로 전이, 진입일은 신호일 기준.
- 다음 실행 때 체결 기록이 없으면 → `미체결`로 한 번 표시하고 이전 상태로 되돌린다 (보유 아님, 재진입 대기 적용 안 함).
- 며칠 늦게 체결 기록이 들어오면 그 시점에 소급 반영 (P3에서 만든 재계산 방식 그대로).
- 2차·3차 추가 매수 신호도 같은 방식: 기존 보유는 유지하고, 추가분만 `주문대기` → 체결 기록으로 확정.
- 테스트 추가: 신호 당일 주문대기 / 다음 날 기록 있음 → 정찰 / 다음 날 기록 없음 → 미체결 표시 후 대기 / 사흘 뒤 기록 입력 → 소급 반영.

## 2. 미체결 표시 시점과 위치

- 신호 **당일**에는 "미체결"이 아니라 보고서 보유 종목 표 아래 안내 줄에 "주문 후 체결 기록 필요: 펩시코 · CSX · ODFL · 엔비디아"로만 표시 (docs/report_template.html의 체결 기록 안내 자리).
- "미체결 (기록 없음)"은 **다음 날** 보고서에만, 같은 안내 줄 위에 따로 한 줄로 표시. 경고 탭의 "데이터 상태"에서는 빼줘.
- 텔레그램도 같게: 당일에는 매수 목록 끝에 "주문 후 체결 기록 필요" 한 줄만, 미체결 목록은 다음 날에만.

## 3. A1 만료 표기

- "전량" 대신 "1차분 (전량)"으로 표기.

## 4. 텔레그램 실제 발송 확인

- `.env`에 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`가 있으면 `python -m engine.daily`로 실제 발송하고, 결과(성공 여부, 보낸 메시지 수, 첨부 파일 이름)를 보고해줘. 토큰 값은 절대 출력하지 마.
- 없으면 발송은 건너뛰고 "토큰 없음"으로 보고.

## 5. 완료 조건과 보고

- `pytest` 전부 통과
- `python -m engine.daily --no-send` 실행 결과: 단계별 종목 수에 `주문대기 4`, 보유 0

```
[P3.1 완료 보고]
테스트: 통과 N / 실패 N
단계별 종목 수(live): ...
텔레그램 글 미리보기: (전체)
텔레그램 발송: 성공 / 토큰 없음 / 실패(사유)
수정·추가 파일 목록: ...
판단이 필요한 부분: (없으면 "없음")
```

"P3.1 pending orders" 메시지로 커밋해줘. 푸시는 하지 마.
