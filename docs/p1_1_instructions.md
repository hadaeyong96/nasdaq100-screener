# P1.1 보완 지시문 — P1 검토 결과 반영

---

P1 완료 보고를 검토한 결과 아래 5가지를 보완해줘. P1 범위 안의 수정만 하고, 신호·상태·텔레그램은 여전히 만들지 마.

## 1. 기준일이 하루 늦은 원인 확인 (최우선)

- 보고의 기준일은 2026-09-21인데, 실행 시점(한국시간 9월 23일 오후)에는 미국 9월 22일 종가가 이미 확정돼 있어야 해.
- NVDA, AAPL을 캐시 없이 새로 받아 yfinance 원본의 마지막 3행(날짜, OHLCV, NaN 여부)을 그대로 출력해줘.
- 9월 22일 봉이 버려졌다면 어떤 규칙 때문인지(장 마감 판정, NaN 제거 안전장치, 캐시 신선도 판정) 밝히고 고쳐줘.
- NaN 제거 안전장치는 "마지막 봉의 open/high/low/close 중 NaN이 있을 때만" 버리도록 좁혀줘. volume만 NaN이거나 0인 경우는 버리지 말고 경고만 남겨.

## 2. 구성 종목은 공식 출처에서 받기

- 구성 종목을 모델 기억으로 매핑하지 마. 이번 목록은 틀린 부분이 있어: SpaceX는 2026년 6월 나스닥에 상장(티커 SPCX)했고 7월 7일 나스닥 100에 편입됐어. 제외하면 안 돼.
- 출처 우선순위: (1) Invesco QQQ 보유 종목 파일 (2) Nasdaq 공식 나스닥 100 구성 종목 페이지 (3) 위키백과 (4) `data/universe_fallback.csv`
- 어느 출처에서 받았는지 실행 로그에 남기고, 결과 종목 수가 100 안팎이 아니면 경고해줘.
- "Honeywell Technologies"처럼 티커가 불확실한 종목은 위 출처로 확인해서 확정해줘.
- `universe_fallback.csv`를 공식 출처 결과로 다시 만들고, 파일 맨 위 주석에 출처와 날짜를 적어줘.

## 3. 상장 기간이 짧은 종목 처리

- SPCX처럼 상장 후 거래일이 적은 종목은 일목 구름(최소 78거래일)이나 볼린저 백분위(120일)가 NaN이 돼.
- `compute_indicators` 결과에 `bars` (보유 거래일 수) 열과, 지표별 계산 가능 여부를 알 수 있는 `insufficient_history` 플래그를 추가해줘.
- p1_report의 RSI 하위 10 표는 RSI 계산이 가능한 종목(15거래일 이상)이면 포함하고, 데이터 부족 종목은 별도로 목록을 출력해줘.
- 이 경우를 테스트로 추가해줘 (짧은 합성 데이터에서 예외 없이 동작, 플래그가 정확한지).

## 4. 학교 네트워크 TLS 우회 설정

- 이 PC는 학교 네트워크라 yfinance의 TLS 인증서 검증이 막혀 `YF_DISABLE_CURL_CFFI=1`이 필요했어.
- 코드에 하드코딩하지 말고, 프로젝트 루트의 `.env` 파일에 있으면 읽도록 해줘 (`python-dotenv` 사용, requirements에 추가).
- `.env.example` 파일을 만들어 이 변수를 주석과 함께 넣고, `README.md`를 새로 만들어 "실행 방법"과 "학교·회사 네트워크에서 인증서 오류가 날 때" 항목을 짧게 적어줘.
- 이 학교 PC용 `.env`는 실제로 만들어 둬 (.gitignore에 이미 포함).

## 5. 대조표를 붙여넣기 쉬운 형태로

- 터미널 출력이 잘려서 대조표를 읽을 수 없었어.
- `outputs/parity_check.md`와 `outputs/rsi_bottom10.md`를 마크다운 표로 추가 저장해줘. 숫자는 소수 둘째 자리.
- 대조표에 `기준일 종가 데이터 출처(yfinance)`와 `일목 이동 칸수 D` 값을 표 위에 한 줄로 적어줘.
