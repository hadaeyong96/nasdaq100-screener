CLAUDE.md, docs/strategy_v3.md 10~11장, docs/report_template.html을 먼저 읽고 P3 범위만 구현해줘.

## 0. 운용 모드 정리 (먼저 처리, 가장 중요)

P2.1 결과에서 오늘 신호 4개가 전부 "동시 보유 한도"로 막혔는데, 그 8개 자리를 차지한 건 되돌려 보기가 만든 **가상 보유**였어. 사용자는 아직 아무것도 사지 않았으니 이건 틀린 결과야. 모드를 둘로 나눠줘.

- `config.yaml`에 `mode: live | paper` (기본 live)
- **live 모드**: 보유는 오직 `data/fills.csv`의 실제 체결 기록으로만 만든다. 가상 체결 없음. 매수 신호를 냈어도 체결 기록이 없으면 보유가 아니다.
  - 상태는 "지금까지의 신호 기록 + 실제 체결 기록"으로 매번 다시 계산해도 같은 결과가 나오게 해줘. 사용자가 며칠 늦게 체결 기록을 넣어도 다음 실행에서 올바른 단계·손절가로 반영돼야 해.
  - 전날 매수 신호에 체결 기록이 없으면 보고서에 "미체결 (기록 없음)"으로 표시하고 보유로 잡지 않는다.
- **paper 모드**: 추천대로 체결됐다고 가정하는 모의 운용. DB는 `data/paper_state.db`로 분리해서 live와 절대 섞이지 않게.
- 두 모드 모두 **오늘부터 시작**한다. 60거래일 되돌려 보기(`--replay`)는 테스트와 백테스트(P5)용으로만 남기고, 운용 시작 때 기본으로 쓰지 않는다.
- 현재 `data/state.db`는 가상 보유가 들어 있으니 백업(`state_replay_backup.db`)하고 live용으로 새로 만든다.
- 보고서와 텔레그램 맨 위에 현재 모드를 표시한다 (예: "실전" / "모의").

## 1. 과열 골든크로스는 정보로 기록

P2.1 판단 1번 답: 신호 조건은 원안 그대로 둔다. 대신 "MACD 골든크로스가 났지만 그날 RSI가 70 이상이라 신호가 아닌 종목"은 `filtered` 정보로 기록해서 보고서 "걸러진 신호" 탭에 "과열 (RSI 70 이상)"로 보여줘. 매수 추천은 하지 않는다.

## 2. 체결 기록 파일 개선 (data/fills.csv)

- 열 이름을 한글로: `날짜, 종목, 차수, 매수매도, 체결가, 수량`
  - 차수 값: `1차, 2차, 3차, 재진입`
  - 매수매도 값: `매수, 매도`
- 기존 영어 형식(date, ticker, unit, side, price, qty / unit 1·2·6·9 / side buy·sell)도 계속 읽는다.
- 날짜는 `2026-09-23`, `2026/9/23`, `2026.9.23` 모두 받는다. 엑셀이 저장한 UTF-8(BOM 포함)과 CP949 인코딩 둘 다 읽는다.
- 잘못된 줄(모르는 종목, 차수 오류, 음수 수량 등)은 건너뛰고 보고서 경고 탭과 실행 로그에 "체결 기록 오류: N번째 줄 ..."로 알려준다.
- `data/fills.example.csv`를 한글 형식으로 바꿔줘.

## 3. HTML 보고서 (notify/report_html.py)

- `docs/report_template.html`의 구조·디자인·스크립트를 그대로 따른다. 템플릿 엔진은 Jinja2를 쓰고 requirements에 추가.
- 출력: `outputs/report_YYYY-MM-DD.html` (외부 파일 없이 한 파일)
- 구성 순서: 한 줄 요약 → 계좌 금액 입력 → 탭(신규 매수[1차·2차·3차·재진입] · 매도·손절 · 보유 현황 · 관찰 목록 · 걸러진 신호 · 경고 · 규칙) → 내 보유 종목 표 + 체결 기록 안내 → 푸터
- 계좌 금액 입력칸의 계산 설정(CFG)은 config.yaml 값으로 채운다. 매수 행에는 data-stage, data-limit, data-stop을 넣는다.
- 체결 기록 안내의 파일 경로는 실제 프로젝트 경로로 채운다.
- 빈 섹션은 "오늘 해당 종목 없음"으로 표시.
- 표기 규칙: "묶음" 대신 "1차분 매도(11%)·2차분(22%)·3차분(67%)·전량", "휩소" 대신 "잦은 교차 (횡보)", E1·E2·E3는 "모멘텀 약화·추세 약화·구조 붕괴"와 함께 표기.
- 경고 탭은 보유 종목만. 데이터 지연·구멍, 실적일 확인불가, 체결 기록 오류는 경고 탭 아래 "데이터 상태"로 따로.
- **통과 현황**(1차 RSI 30 돌파 → 2차 MACD 골든크로스 → 3차 일목구름 4요소 → 4차 매매금지 필터 → 5차 보유한도)은 보고서에 표시하지 않고 `outputs/funnel_YYYY-MM-DD.csv`와 events에만 기록.

## 4. 텔레그램 요약 (notify/briefing.py, notify/telegram.py)

- 휴대폰에서 읽기 좋은 짧은 글 한 통 + HTML 보고서 파일 첨부.
- 글 구성: 제목(기준일, 모드) → 한 줄 요약 → 신규 매수(종목 한글명, 차수, 지정가, 수량, 손절가) → 매도·손절(종목, 신호, 매도 범위, 수량) → 보유 종목 중 오늘 신호 있는 것 → 미체결 알림 → "상세는 첨부 보고서".
- 토큰과 채팅 ID는 `.env`의 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`에서 읽는다. `.env.example`에 항목 추가.
- 토큰이 없으면 보내지 않고 `outputs/telegram_YYYY-MM-DD.txt`에 저장만 한다. 에러로 멈추지 않는다.
- 4096자 넘으면 나눠 보내기, 실패 시 3번 재시도, 같은 기준일 중복 발송 방지(runs 기록 확인).

## 5. engine/daily.py 연결

- `python -m engine.daily` : 판정 → 보고서 → 텔레그램(토큰 있으면)
- `--no-send` : 보고서만 만들고 발송 안 함
- `--mode paper` : 설정보다 우선하는 모드 지정

## 6. tests/

- live 모드: 체결 기록 없으면 보유 0, 가상 체결 없음 / 늦게 넣은 체결 기록이 다음 실행에 올바르게 반영 / 미체결 표시
- paper와 live DB 분리
- 체결 기록: 한글·영어 열, 날짜 3형식, BOM·CP949, 오류 줄 건너뛰기
- 보고서: 모든 섹션이 비어 있어도 렌더링 성공, 매수 행 data 속성 포함
- 텔레그램: 4096자 분할, 토큰 없을 때 파일 저장
- 모두 네트워크 없이

## 7. 완료 조건

- `pytest` 전부 통과
- live 모드로 `python -m engine.daily --no-send` 실행 → `outputs/report_기준일.html` 생성
- paper 모드로 한 번 실행 → 별도 DB 생성 확인
