# P3.6 지시문 — 종목 차트 링크 + 신규 매수 "전체" 탭

---

보고서 사용성을 두 가지 다듬어줘. 스케줄·드라이브는 여전히 만들지 마.

## 1. 종목 티커에 Finviz 차트 링크

- 보고서의 **모든 표**(신규 매수·매도·손절·보유 현황·관찰 목록·걸러진 신호·경고)에서 티커를 Finviz 종목 페이지 링크로 만든다.
  - 주소: `https://finviz.com/quote.ashx?t=티커&p=d` (일봉 차트)
  - 새 창으로 열기: `target="_blank" rel="noopener"`
  - 티커 형식은 yfinance 형식 그대로(`-` 사용, 예: BRK-B).
  - `docs/report_template.html`의 `a.tk` 스타일(점선 밑줄, ↗ 표시)을 그대로 따른다.
- **종목명과 티커를 별도 칸으로 분리**: 모든 표의 첫 두 칸을 `종목`(한글명, 없으면 짧은 영문명, `class="nm"`)과 `티커`(Finviz 링크)로 나눈다. 한 칸에 "PEP 펩시코"처럼 합쳐 쓰지 않는다. 빈 표의 colspan도 1씩 늘린다. 휴대폰 카드 보기에서는 종목명이 카드 제목, 티커는 그 아래 칸.
- 대기자금 QQQM 줄도 같은 방식으로 링크.
- 텔레그램 글에는 링크를 넣지 않는다 (글은 짧게 유지).

## 2. 신규 매수 "전체" 하위 탭

- 신규 매수 탭의 하위 버튼 맨 앞에 **"전체 (N)"** 를 추가하고, 보고서를 열면 이 탭이 **기본 선택**되게 한다.
- 전체 표는 1차·2차·3차·재진입 신호를 한 표에 모으고, 종목 다음에 **차수** 칸을 넣는다 (1차 정찰 / 2차 확인 / 3차 확정 / 재진입). 정렬은 점수 높은 순.
- 칸: 종목 · 티커 · 차수 · 결정 · 지정가 · 수량 · 투입금액 · 손절가 · 손절폭 · 점수 · 비고 (11칸). 차수별 표는 종목 · 티커 · 결정 · 지정가 · 수량 · 투입금액 · 손절가 · 손절폭 · 점수 · 비고 (10칸).
- 계좌 금액 재계산이 전체 표와 차수별 표 **양쪽 모두** 갱신되게 한다 (같은 종목이 두 표에 나오므로 각 행에 data-stage/limit/stop 유지).
- 종목이 있는 하위 버튼은 초록 테두리, 0건인 버튼은 흐리게 표시.

## 3. 테스트와 완료

- 링크 href 형식, 전체 탭 기본 선택, 전체 표 행 수 = 차수별 합, 0건 버튼 흐림 표시 테스트
- `pytest` 전부 통과
- 실전 모드 보고서를 상태 재처리 없이 다시 만들고 `--resend`로 발송 (토큰 값 출력 금지)

```
[P3.6 완료 보고]
테스트: 통과 N / 실패 N
링크 적용 표: ...
전체 탭 행 수 / 차수별 합: ...
발송 결과: ...
수정 파일 목록: ...
판단이 필요한 부분: (없으면 "없음")
```

"P3.6 finviz links and all-buys tab" 메시지로 커밋해줘. 푸시는 하지 마.

## 4. 계좌 금액 입력칸을 규칙 탭으로 이동 (추가)

- 첫 화면의 계좌 금액 입력줄을 **규칙 탭 맨 위 "계좌 금액 계산기"** 로 옮긴다. 첫 화면에는 요약줄 → 탭만 남긴다.
- 계좌 기준 금액은 머리글의 "계좌 기준 $X"(config.yaml 값)로만 보여준다.
- 계산기 기능(단계별 위험 예산 표시, 수량·투입금액 재계산)은 그대로 동작해야 한다. 파란 배경 강조는 없앤다.
- `docs/report_template.html`의 배치를 그대로 따른다.

## 5. 요약줄 제거 (추가)

- 제목 아래 요약줄(신규 매수·매도·손절·보유·걸러진 신호·신규 위험)을 **삭제**한다. 건수는 탭 옆 숫자로 충분하다.
- 보유 탭 숫자는 `보유 현황 5/8`처럼 **보유 수/한도**로 표시.
- "신규 위험 합계"는 신규 매수 탭 안내문 맨 앞에 `오늘 신규 위험 $1,637 (계좌의 1.6%)`로 표시 (계산기로 금액을 바꾸면 함께 갱신).
- 텔레그램 글은 변경 없음.
- `docs/report_template.html`의 배치를 그대로 따른다.

## 6. 자금 계획 기반 금액 산정 + 원화 표기 (추가, 중요)

종목별 금액 입력칸은 만들지 않는다. 대신 **자금 계획**에서 금액이 자동으로 정해지게 한다. `docs/report_template.html`의 배치·스크립트를 그대로 따를 것.

### 6-1. 설정 (config.yaml)
- `account.total_krw`: 총자금(원), 예: 100000000
- `plan.strategy_limit_pct`: 전략 한도(%), 기본 60 — 신호 종목에 쓸 수 있는 최대 비중
- `plan.cash_buffer_pct`: 5, `plan.max_slots`: 8
- 기존 `equity_usd`는 제거하고, 달러 계산이 필요하면 `total_krw ÷ 환율`로 구한다.

### 6-2. 금액 산정 규칙 (core/sizing.py)
- 종목당 슬롯 = 총자금 × 전략 한도 ÷ 최대 보유 종목 수
- 차수별 목표 금액 = 슬롯 × (1차 1/9, 2차 2/9, 3차 6/9, 재진입 1)
- 수량 = min(목표 금액 ÷ 환율 ÷ 지정가, **위험 상한 수량**)
  - 위험 상한 수량 = (총자금 × 2% × 차수 비중, 재진입은 총자금 × 1%) ÷ 환율 ÷ 주당 위험 (주당 위험 = (지정가 − 손절가) + 지정가 × 갭 여유, 최소 지정가의 1%)
  - 위험 상한으로 줄었으면 비고에 "손절이 멀어 수량 축소"
- **2·3차 몫 예약**: 1차를 보유 중인 종목은 슬롯의 8/9, 2차까지 보유 중이면 6/9를 예약으로 잡는다.
- 남은 한도 = 전략 한도 − 보유 평가금액(신호 종목) − 예약. 오늘 신규 매수는 점수 높은 순으로 (투입금액 + 새로 생길 예약)을 남은 한도에서 차감하고, 부족하면 수량을 줄이거나 0으로 하고 비고에 "남은 한도 부족".
- QQQM 목표 = 총자금 × (1 − 현금 버퍼) − 신호 종목 보유 − 오늘 신규.

### 6-3. 보고서 표시
- 탭 위에 **자금 계획 줄**: 전략 한도 · 종목당 슬롯 · 보유 · 2·3차 예약 · 오늘 신규 · 남은 한도 · QQQM + 막대 그래프 (템플릿 그대로). `<body>`에 data-fx, data-date, data-total, data-limit-pct, data-used, data-reserved를 채운다.
- 신규 매수 표(차수별): 종목 · 티커 · 결정 · 지정가 · 수량 · 투입금액 · 손절가 · 손절폭 · 최대 손실 · 점수 · 비고 (11칸). "전체" 탭은 티커 다음에 차수 칸 (12칸). 전체 탭과 차수별 탭에 같은 종목이 나와도 **합계는 한 번만** 계산.
- **금액은 원화로 표기**: 투입금액, 최대 손실, 예상 손익, 평가금액, 평가손익, 자금 계획 줄 모두 `73만`, `1억 2,300만` 형식. **가격(지정가·손절가·평균단가·종가)은 주문에 쓰므로 달러 유지.**
- 하위 탭 이름: `1차 정찰 · 슬롯의 1/9`, `2차 확인 · 2/9`, `3차 확정 · 6/9`, `재진입 · 슬롯 전체`.
- 규칙 탭의 계산기는 **총자금(원)과 전략 한도(%)** 두 칸으로 바꾸고, 바꾸면 자금 계획 줄과 수량이 다시 계산된다 (화면 확인용, 기준값은 config).

### 6-4. 환율
- 원/달러 환율(yfinance `KRW=X`)을 매일 받아 기준일 종가 환율을 쓴다. 머리글에 `총자금 1억 원 · 환율 ₩1,380/$ (9/22)` 표시. 못 받으면 직전 캐시 값 + 경고 탭 표시.

### 6-5. 텔레그램
- 변경 없음 (티커 요약 유지).

### 6-6. 테스트
- 슬롯·차수 금액, 위험 상한으로 축소, 예약 차감, 남은 한도 부족 시 축소·0, 점수순 배분, 원화 표기 형식(만·억), 환율 캐시, 전체 탭 중복 합산 방지.
