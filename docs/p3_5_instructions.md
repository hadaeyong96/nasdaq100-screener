# P3.5 지시문 — 손절 근접·손절 예약 알림

---

P3.4가 끝난 상태에서 진행해줘. 보유 종목의 손절 예약 주문을 사용자가 놓치지 않도록 알림을 추가해. 스케줄·드라이브는 여전히 만들지 마.

## 1. 알림 세 가지

| 알림 | 조건 | 보고서 표시 (보유 현황 탭의 비고 칸 + 경고 탭) |
| --- | --- | --- |
| 손절 근접 | 종가가 손절가보다 `stop_near_pct`(기본 3%) 이내로 위에 있음 | `손절 근접 · 예약 $손절가 확인` (주황 배지) |
| 손절 예약 변경 | 손절가가 바뀐 날 (예: 3차 매수 후 구름 하단으로 상향, 추가 매수로 기준 변경) | `손절 예약 변경 · $이전 → $새 가격` (파란 배지) |
| 손절 예약 필요 | 새로 체결 기록이 들어온 날 (1차·2차·3차·재진입 매수) | `손절 예약 필요 · $손절가` (파란 배지) |

- `config.yaml`에 `alerts.stop_near_pct: 3` 추가.
- 여러 알림이 겹치면 우선순위: 손절 근접 > 손절 예약 변경 > 손절 예약 필요. 배지는 하나만, 나머지는 경고 탭에 모두.
- 손절 신호(종가 < 손절가)가 난 날은 매도 탭에 나오므로 위 알림은 표시하지 않는다.
- 손절가 변경 이력은 events에 `stop_changed`로 기록 (이전값, 새값, 사유).

## 2. 텔레그램 (짧은 형식 유지)

알림이 있을 때만 한 줄 추가:

```
🛡️ 손절 예약 · AMZN(근접) TSLA(변경) CMCSA(신규)
```

## 3. 테스트

- 근접 경계: 3.0% 이내 표시, 3.1%는 미표시
- 3차 매수로 손절가가 올라간 날 `stop_changed` 기록과 배지
- 새 체결일에 "손절 예약 필요"
- 손절 신호일에는 근접 알림 없음
- 텔레그램 한 줄 형식

## 4. 완료

- `pytest` 전부 통과
- 보고서 하단의 "내 보유 종목" 표는 삭제됐어. 손절 관련 배지는 보유 현황 탭의 비고 칸에 같은 배지 스타일(b-warn, b-info, b-sell)로 넣어줘.

```
[P3.5 완료 보고]
테스트: 통과 N / 실패 N
오늘 손절 관련 알림: (표, 없으면 "없음")
텔레그램 글 미리보기: ...
수정 파일 목록: ...
판단이 필요한 부분: (없으면 "없음")
```

"P3.5 stop order alerts" 메시지로 커밋해줘. 푸시는 하지 마.

## 5. 손절 신호일의 주문 안내 (추가)

손절이 필요한 날(종가 < 손절가)에는 매도·손절 탭에 **주문 안내** 칸을 추가해 아래 문구를 넣어줘. 다른 매도 신호(E1·E2·E3·1차 만료)에도 같은 칸을 쓴다.

- 손절: `손절 예약 확인 · 증권사 손절 예약($손절가)이 오늘 체결됐으면 체결 기록만 입력. 체결 안 됐으면 다음 거래일 장 시작 시 N주 전량 시장가 매도 예약`
- E1·E2·E3·1차 만료: `다음 거래일 장 시작 시 N주 매도 주문 예약`
- 보유 현황 탭 비고 칸: 손절이면 `손절 · 예약 체결 확인` (빨강 배지). 손절이 있는 종목은 근접·변경·신규 알림보다 이 배지가 우선.
- 텔레그램: 손절이 있으면 매도 줄에 `ROP(손절·예약 체결 확인)`처럼 표시.
- `config.yaml`에 `orders.stop_fallback_type: 시장가` 추가 (문구에 쓰는 주문 방식, 지정가로 바꿀 수 있게).
- 테스트: 손절일 주문 안내 문구, 배지 우선순위, 텔레그램 표시.
